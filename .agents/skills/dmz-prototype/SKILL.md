# dmz-prototype

Read the [project workflow bridge](../../../docs/agents/workflows.md) for authority, scope, task selection and evidence rules. Consult only the relevant [repository map](../../../docs/agents/repository-map.md) and [domain guide](../../../docs/agents/domain.md).

State the question and the acceptance observation first. Use fictional in-memory state, clearly labeled, and keep the experiment out of public production routes and real profiles. Make it runnable with one command or a self-contained local HTML file, with no CDN requirement. Compare only meaningful alternatives. For layout questions inspect the actual rendered narrow width and enlarged-text state, not just the source. Verify that any served preview has the correct content type and works before linking it. Capture the verdict and artifact pointer in the feature; production adoption remains an implementation task.
