# Scoped Spec Kit prompt starters

> Historical planning snapshot (21 October 2026), preserved as product context. References below to proposed setup, pending licensing or absent repository authorization describe the earlier planning stage, not current repository status. The repository is now being bootstrapped; original project code is MIT licensed. See [current README](../README.md) and [current Spec Kit lifecycle](spec-kit-cycle.md) for active setup and process. Product features and production data remain unimplemented. This snapshot does not authorize external actions.
These are proposed future prompts, not commands already executed. Run one step, inspect its output, then proceed. Resolve the designated feature directory explicitly. The roadmap's later tasks are context, not permission for feature 001 to implement every slice.

## Constitution
`$speckit-constitution Adopt the reviewed constitution in this planning pack. Preserve mobile/accessibility, factual provenance, local private state, safe portable packs, explainable planning, independent testing and small reversible slices. Do not change deployment or account permissions.`

## Feature 001: guide foundation and one useful plan
`$speckit-specify Build only S0-S2: dark-first accessible public guide/search/item and recipe details, sourced/unknown facts, local inventory, one selected goal, shortage/currency/gate explanation and profile backup/restore. Use labeled synthetic fixtures until verified data is approved. Do not implement general content-pack editor, multi-goal optimization, maps, accounts or Discord integrations in this feature.`

`$speckit-clarify Resolve inventory pool eligibility, consumed vs retained requirements, prerequisite confidence, local completion semantics and first-release content scope. Preserve unresolved numerical game facts rather than inventing answers.`

`$speckit-plan Compare the bounded static-first architecture candidates, then use the selected one with pure TypeScript domain logic, shared portable schema and transactional local storage. Include no-JavaScript public reading, migration/recovery, selected-route cycle checks and explicit tested contracts. Treat current technical choices as recommendations pending spike, not already-installed dependencies.`

`$speckit-checklist Review requirement clarity for safe imports/backups, accessible mobile states, factual disputes, inventory conservation and unsupported mechanics. This is requirements-quality review, not permission to check off implementation.`

`$speckit-tasks Generate only feature 001 tasks with test tasks explicitly included per story. Use S0-S2 identifiers as traceability context; do not pull later roadmap work into this feature. Include dependencies and disjoint-file parallel markers.`

`$speckit-analyze Check scope, requirement/task/test coverage, circular dependencies, contradictory mechanics and unsupported claims. Report only; remediate the source artifacts before implementation.`

After owner-approved scope/environment and satisfied gates:
`$speckit-implement Implement only the approved feature 001 phase. Do not weaken tests, self-approve reviewer checklists, publish assets, deploy, or mutate remote repository settings. Report evidence and blockers.`
`$speckit-converge Assess this implemented feature against its artifacts; append missing work, then rerun implementation and verification until gaps are resolved.`
