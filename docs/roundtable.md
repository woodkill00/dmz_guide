# Architecture, delivery and QA roundtable

These are proposals and recorded technical critiques, not user approvals or claims of implemented results. Separate design, domain, maps/security, screenshot and adversarial-review perspectives contributed. Detailed research accompanies this synthesis.

## Fourteen delivery proposals with trade-offs
1. Static-first guide with interactive islands. Benefit: readable/searchable public content without hydrating everything. Cost: island state/routing coordination. Decision: preferred, compare against one full-framework alternative in a bounded spike.
2. Local-first player state, no accounts for core use. Benefit: immediate use, low operations, privacy. Cost: no automatic multi-device restore and browser eviction risk. Decision: accept with backup, storage-status and failure tests.
3. Shared portable JSON Schema contract. Benefit: editor, importer and compiler agree. Cost: migrations and schema/type generation discipline. Decision: accept; do not hand-maintain divergent validators.
4. Compile public content during publishing. Benefit: fast reads and auditable updates. Cost: publishing pipeline latency. Domain critique: this cannot prohibit private runtime imports. Reconciled: same validation/compilation rules run privately offline, with no automatic publication.
5. Pure deterministic planning engine. Benefit: testable and explainable. Cost: cannot promise a global optimum across every alternative. Decision: pinned-route DAG, supported mechanics only; requirements plan separate from executable-now schedule.
6. Feature-sized Spec Kit cycles. Benefit: reviewable context and early useful releases. Cost: more repeated coordination. Decision: each slice gets gates and convergence, one constitution governs all.
7. Fixed FR/task/acceptance traceability. Benefit: no quiet scope disappearance. Cost: maintenance when scope changes. Decision: check orphan requirements/tasks each analysis pass.
8. Five or fewer mobile tabs. Benefit: thumb reach and stable navigation. Cost: some features move behind More. Design critique: Community wastes in-run prominence and Guide/Plan/Progress overlap. Reconciled: Home/Search/Map/Saved-or-Plan/More candidate; prominent home planning entry and contextual actions; test labels.
9. Sticky now/later context. Benefit: reduces memory load during collection. Cost: stacks with bottom navigation/map sheets. Reconciled: collapsible inline summary, one dominant bottom surface, explicit safe-area and keyboard testing.
10. Asset manifests instead of embedded base64 JSON. Benefit: smaller diffs and explicit rights/hash metadata. Cost: manifests alone are not portable pictures. Security critique accepted: self-contained bounded asset bundles must finish S4; references-only explicitly labeled and cannot pass the picture-portability gate.
11. Adversarial test fixtures before implementation. Benefit: reveals batch, stock and import bugs cheaply. Cost: more initial modeling. Decision: cycle checks start before single-goal planning; shared one-time unlock and strict-reservation examples mandatory.
12. Accessible list as equal map interface. Benefit: useful without imagery/gestures/network. Cost: editorial directions and synchronized state. Decision: include floor/grid/landmark/action parity, not merely a list of names.
13. Defer server, bot, realtime and optimizer. Benefit: smaller security/operations footprint. Cost: less social novelty and cross-device convenience. Decision: requested community features still delivered through verified Discord and reviewed corrections; optional infrastructure is separately specified when demand warrants it.
14. Measured release evidence, not “perfect” promises. Benefit: defensible quality. Cost: manual mobile/content review remains necessary. Decision: independent reviewer plus tests, observed benchmark profile and explicit remaining risks.

## Two-way challenges that changed the plan
- Domain challenged build-only imports and per-goal rounding. Accepted private runtime validation and aggregate shared demand before batch rounding. Delivery challenged “feasible” wording: all-goal demand may be infeasible. Domain agreed on “requirements plan,” with a separately simulated executable schedule.
- Design challenged fixed tab labels and persistent bars. Delivery accepted navigation testing but challenged hiding the core planner under Saved. Design agreed to home “Plan my next upgrade” and contextual “Add to plan.” Neither side claims its favorite label is proven.
- Security challenged picture-manifest portability. Delivery proposed a safer manifest+raster first step, security pointed out missing assets prevent self-contained portability. Reconciled reference-only interim formats plus full bounded bundle before S4 completion.
- Security challenged coordinate normalization tied to image pixels, unbounded stale trust, and reputation-as-proof. Accepted versioned canonical space, explicit known-unsafe revocation vs stale warnings, and independent evidence review. Costs: calibration/migration work, no fresh revocation knowledge offline, and ongoing editorial effort.
- Screenshot review confirmed currency/gates/effects distinctions but rejected invented prerequisites from Roman numerals and inferred backpack-slot meaning from “MAX.” Only directly visible recipe requirements/effects inform provisional observations; no player holdings are included.
- Adversarial review found shared prerequisite double-counting, priority reservation ambiguity, projected surplus conflation and task dependency contradictions. Corrected plan semantics and A18-A24; moved cycle/format/analysis gates earlier. This is substantive review, not unanimous endorsement without challenge.

## Continuing disagreements resolved by evidence, not votes
Navigation wording requires task testing. Framework choice requires the minimal public-route/planner prototype. Image-bundle limits require mobile memory tests. Printer unlock source conflict remains disputed until stronger version-specific evidence. Community scope requires owner/moderator commitments. No number of agents voting can settle these empirical or owner decisions.
