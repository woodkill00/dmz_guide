# Edit a guide page

Run `npm run author`. On Windows, `scripts\start-local.cmd -Author` explicitly starts the reader, map and author service. Reader: http://127.0.0.1:4173/. Editor: http://127.0.0.1:4174/. Choose **Edit page** on the exact Order, item, upgrade, weapon, camo or key page. Content Studio remains available for catalog-wide work.

Use **Content** for facts, **Layout** for sections and **Photos** for pictures. Click a block in the live preview to select its controls; links select by default, with **Follow preview links** available when you want to navigate. Drag panel dividers or use their width controls, collapse either side and retain the arrangement in this browser. Below900px available width, switch between Outline, Preview and Fields tabs.

Add sections and pictures between task blocks; use buttons or drag sections to reorder. Search the outline, select several sections and move, duplicate or remove them together. Templates provide tips, walkthrough, location/photo, requirements and two-column starting points. Save selected custom sections as reusable layouts; their imports require review and use fresh IDs. Managed canonical facts cannot be copied into a reusable layout. Ctrl/Cmd+S reviews or saves the reviewed draft; native text-field undo remains available.

Pictures support file picker or drop, visual crop with numeric alternatives, eligible library thumbnails, placement descriptions, captions, fit and focal position. Uploads require rights information and normalize to PNG. Original and output resolution feedback helps avoid unwanted enlargement. The existing nine-picture/record and2MiB/picture limits remain.

**Content** changes canonical facts; **All structured record fields** exposes schema-guided fields. Orders have individual task controls. A changed cost or mission step feeds the ordinary planner after rebuilding and the normal explicit profile version rebind. Page layout never grants inventory or completion. Chapter rewards have their own **Edit chapter report** link. Specialized data retains source validators; local corrections are distinguished from captured source reports.

Choose **Review changes**, follow any linked field errors, inspect readable before/after changes and semantic/version impact, then **Save to repository**. Advanced version controls offer an explicit next-version suggestion when needed. Saving changes checkout files, not Git history. The saved author preview is immediate. **Save & refresh reader** also runs the fixed local build; its result is separate from Save. A failed refresh retains the saved content and previous working reader. **Retry reader refresh** does not save the page twice. You can still run `npm run build`, then review and commit intended files normally. Approved public accounts remain future work.

Shared acquisition/camo roster names and categories, and key location names/grid coordinates, are read-only here because they must agree with other source catalogs. Their fields explain the owning source workflow. Supported requirements and acquisition methods remain editable; IDs and downloaded-image registrations also retain their owning tools.

Custom item layouts retain their inventory, build-target and collection tools. Use Move controls to relocate canonical sections; repeated canonical anchors are rejected rather than publishing ambiguous links or controls. Reference cards link exact catalog records and locations. Editing after an import review expires that plan, so select the bundle again before applying it over newer work.

Saved record pages offer a visible **Edit page** for items/weapons, recipes, objectives/upgrades, guides, maps and locations when that exact record exists in the published repository catalog. On an item page, **Edit & photos** holds secondary actions. **Edit private copy** remains separate; private-only records never receive a guessed repository link. Repository editing does not automatically copy private changes into source files. Upgrade rows provide **Open page / edit**, and item-maintenance names open individual detail pages with direct composer links alongside them. Weapon stats, acquisition references, camos and keys keep their dedicated source editors; interactive map canvases and boss counters retain their owning workspace tools.

Recovery drafts belong to this browser and author origin; they are not inventory backups or sync. **Backups & transfer** exports unfinished drafts or page bundles with pictures. References-only bundles require matching eligible library assets. Imports require explicit preview/apply and then review/save. Keep the original export when target/source baselines differ.

**History & recovery** also keeps disk checkpoints for this checkout, including prepared pictures. A different browser can compare one and restore it into a draft. Another tab's unfinished checkpoint pauses automatic disk writes until you explicitly compare or replace it. Current and previous copies can be exported; corrupt or future data is retained for inspection rather than silently replaced. Disk checkpoints do not publish content or replace inventory backups.

Each Save transaction retains the original/new saved page as local revision snapshots, with the newest five retained automatically. Compare a revision, confirm its source/picture availability and **Restore into draft**; review and Save are still required. Unsupported or missing referenced source pictures block restoration. History, checkpoints and refresh receipts live under ignored `.author-state/`; they are local recovery, not Git history or cloud sync. The combined payload limit is256MiB/4096 files; capacity errors preserve existing data and ask for explicit cleanup.

On conflict, use **Compare current repository with this draft**, export the draft and reconcile deliberately. No automatic overwrite/merge occurs. After a lost save response, **Check save status** reuses the original operation without writing twice. Resolve its outcome before another save. Existing `npm run author:recover` handles interrupted journals; corrupt/future recovery records are retained for export.

Custom documents live in `content/page-documents/` with a hash-bound manifest. Removed sections retain old link anchors with a visible notice. Git history and the ignored transaction journal provide separate recovery history. Private inventories, completion and cached screenshots are not promoted into repository content.

Developer verification: `node tests/browser/page-editor-run.mjs` runs the core, media/accessibility, failure-recovery and adapter journeys. `node tests/browser/page-editor-experience.mjs` adds Order/item composition, cross-browser disk recovery, revision restore and independent refresh retry; `node tests/browser/page-editor-experience-adverse.mjs` holds asynchronous responses to verify ownership and comparison ordering. Each runs Chromium, Firefox and WebKit against disposable checkouts. Install root/map development dependencies and the three Playwright browsers first. The dedicated GitHub workflow job uses these runners; local results do not claim that GitHub has executed it.
