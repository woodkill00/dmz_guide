# Domain documentation

Use [GLOSSARY.md](../../GLOSSARY.md) for meanings and [existing ADRs](../adr/decisions.md) for decisions. Keep paths and commands in the [repository map](repository-map.md), implementation acceptance in owning specs, and source claims in content provenance.

Read relevant terms before editing calculations/state. Unknown is distinct from zero; a recipe identity is distinct from an ownership flag; private saved state is distinct from public source records. Propose consequential definition changes in the active feature instead of silently changing behavior. Add ADRs only for real, consequential trade-offs and mark status explicitly. No glossary entry certifies an untested game mechanic.
