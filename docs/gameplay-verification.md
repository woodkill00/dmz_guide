# Gameplay and road-verification worksheet

Status: **Not executed in real gameplay.** Synthetic tests verify the app, not road passability or game accuracy.

Save a private backup, then open Planner section → Match journal. Start a dated session with selected routes and missions. Record your game build, vehicle, floor and observation context in notes.

1. Choose objectives and check source versions.
2. Build a route and inspect gaps, bridges, gates and off-road connectors.
3. Follow it in the game and mark reached stops manually.
4. Add an owned POI, screenshot or approach note where useful.
5. Check a road segment in gameplay. Save a dated Road verification report with notes and explicit attestation; uncertain access stays uncertain.
6. Record awkward controls, obstructing menus and wrong locations. Mark checklist failures honestly.
7. Capture changed route versions explicitly; starting route/objective snapshots stay frozen.
8. Review temporary marks before ending. Promote only selected marks. End captures mission progress separately and clears captured temporary marks only after successful save.
9. Export the journal, download a private backup and confirm the files actually saved.
10. Preview that backup in Backups, inspect differences and cancel unless replacement is intended. For a real restore, use the existing backup-before-replace gate and check owned data/dependencies afterward.

Reports bind to the exact graph fingerprint. Replacing the graph makes old reports stale; reports do not rewrite route rules or prove access elsewhere. Trace missing roads with the existing editor and author explicit junctions rather than assuming crossings connect.

Keep private screenshots and exports out of public history. Physical-device, screen-reader and real-match results require actual testers; this worksheet does not mark them passed.
