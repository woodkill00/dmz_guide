# DMZ Guide Constitution
Status: proposed planning baseline, 2026-10-21. Not yet ratified or implemented.

1. Player decisions first. Every feature must improve finding, understanding, collecting, crafting, progression, or community contribution. Cosmetic immersion cannot hide critical facts or actions.
2. Mobile and accessibility are foundations. Default dark, optional persisted light preference, semantic HTML, keyboard access, visible focus, non-color status labels, reduced-motion support, and a usable alternative to map gestures.
3. Trust is data. Every published game claim records source, verification state, applicable game/content version and review time. Unknown mechanics remain unknown; synthetic fixtures cannot look like real game data.
4. Portable content and private state. Content packs are versioned and independently validated. Player inventory, progress and goals are separate, local by default, exportable and recoverable. No account is required for the core guide.
5. Explainable planning. Collection recommendations expose goals, quantities, prerequisites, uncertainty and resource allocation. Never promise a global optimum without a defined objective and verified algorithm.
6. Untrusted imports stay inert. Imported text, JSON, archives, images and links cannot execute code. Validate all boundaries, reject dangerous formats and paths, bound resource use, preview changes, preserve the previous valid state.
7. Small reversible vertical slices. Deliver the smallest usable end-to-end journey before broader feature breadth. Dependency boundaries and data contracts are agreed before parallel implementation.
8. Tests accompany behavior. Requirement IDs map to tasks and acceptance evidence. No completion claims based only on code generation, screenshots or checked task boxes.
9. Community with governance. Distinguish private editing from public publishing. Publication requires review, attribution and moderation rules. Discord is optional and cannot be required to read guide content.
10. Measured simplicity. Prefer a static public guide, isolated pure domain logic and local state over premature services. Add a backend only when a measured requirement cannot be met safely otherwise.

Amendments require a reason, affected requirements, migration impact and reviewer acceptance. Record exceptions in an ADR with an expiry/revisit trigger. Security, data-loss and factual-integrity exceptions block release.
