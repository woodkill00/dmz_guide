# Data model
Version1 catalog: checkedAt, provider source/date/status, coverage and weapons. Official progression links and supplemental references are authored in the renderer alongside this catalog, not extra catalog fields. Each weapon uses released roster id/name/category/sourceURL/rows. Row has camo slug/name/group/order/requirement/sourceURL/image{sourceURL,sha256,mime,width,height}. Exact fields and bounded lengths/count/depth/nodes/bytes, fixed CODCentral paths joined to weapon/camo, unique identities/order, allowedgroups. No SVG, executable content, arbitrary URL or private ownership.
Official guidance isn't parsed arithmetic. Shared rows indicate shared application, not independently trackedperweapon. Raw reports retain differences.

## Exact boundary oracle
Catalog exact keys: version,checkedAt,provider,coverage,weapons. version=1; checkedAt/provider.date real ISO calendar YYYY-MM-DD; provider exact {url,date,status}, status=reported and url exact CODCentral hub. coverage1..1000chars. weapons1..256 with unique existing acquisition IDs; this snapshot35. Weapon exact {id,name,category,sourceURL,rows}; id/camoid slug1..100 ASCII lowercase alphanumeric/hyphen, reject constructor/prototype/__proto__; name1..100, category acquisition enum, sourceURL exact hub + weapon + '/'. Each rows25 for current snapshot, max40; total<=1200. Row exact {id,name,group,order,requirement,sourceURL,image}; name1..100, group military|special|completionist|prestige|modeMastery, order consecutive1..25, requirement1..1000 with no controlchars, sourceURL exact weaponURL+'#'+camoid. Image exact {sourceURL,sha256,mime,width,height}; sourceURL exact 'https://codcentral.net/assets/library/mw4/dmz/camos/'+weapon+'/swatch-'+camoid+'.webp'; sha25664lowercasehex; mime=image/webp; width=height=128. JSON<=2MiB, depth<=8, nodes<=40000, stringlimit2000; prohibit prototype keys throughout. Snapshot group counts8/3/4/4/6 (military/special/completionist/prestige/modeMastery); rowIDs uniqueperweapon. Build fails on unreviewed coverage drift.
