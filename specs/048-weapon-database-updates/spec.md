FR001 Populate all33 official launch weapon identities/basic observations, retaining existing four stable IDs and all unrelated pack/profile data. Launch data is dated, not certified current DMZ. Unknown/unavailable/not-applicable values remain distinct. Record source conflicts rather than select arbitrary unlock values.
FR002 Populate reusable standard/Apex attachment identities, reported weapon compatibility and per-weapon effects from researched structured sources; no copied artwork/long descriptions. Preserve source lineage, game/mode/build/date, multiplication semantics and missing effects. No claim of complete verified DMZ stats or exact combined simulation.
FR003 Provide compact searchable/filterable weapon/attachment views, individual weapon details, stats/effects and official patch history accessible from existing navigation and weapon reference. Escape all data, support keyboard/narrow/200%text and state clearly which reports apply to MP, DMZ, shared launch or uncertain mode.
FR004 Provide runnable local CLI commands for on-demand patch checks and check-only automation. Discover official MW4 patch pages through the official patch index plus pinned rolling page. Same-origin exact-path restrictions, bounded bytes/pages/time, no redirects to arbitrary origins, inert HTML parsing, no login/game-file access. Run checks only explicitly; no scheduler or network during build/tests.
FR005 Parse dated mode/weapon/variant/metric change observations and preserve raw units/text and explicit source pointers/review warnings for qualitative changes and parser gaps. Unknown units or ambiguous sections cannot become normalized DMZ numeric values. Retain source/date and prior observations; patch ledger updates do not blindly rewrite incompatible baseline stats. UI exposes latest patch reports separately from original base measurements.
FR006 Check stages an inspectable bounded proposal and reports added/changed/unchanged counts. Explicit apply validates payload, rejects stale database revisions, performs a single atomic database replacement with backup and serialized writer lock, and is a no-op for repeated identical proposals. Source removals do not delete records. Preserve owner edits, report correction history, reject malformed/partial/unrecognized sources and do not silently treat parser failures as no updates.
FR007 Validate populated coverage, schema/links, alias/compatibility/scope/unknowns, malicious inputs, duplicate updates/corrections/CAS/failure safety, parser tables/mode/date/discovery and real live repeated check. Run full runtime, appropriate content/UI regression and three-engine responsive checks; independently review definition/source/implementation and document exact evidence/limits.

Clarifications: requests authorize local collection of previously researched providers and explicit patch updates. No public redistribution/deployment. Updates are command-line features usable manually or from check tasks; no new server or background scheduler. Patch application updates the source-backed change ledger; old base statistics retain their original date/scope rather than being silently replaced. Unsupported patch structures are review warnings, not assumed no-change. Damage/TTK remain unknown unless an applicable numeric observation exists.
