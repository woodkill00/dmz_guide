# Bounded contracts

## Intelligence v1

Fixed path content/weapon-intel.json, maximum8MiB UTF-8 JSON, depth20 and150000 total value nodes, matching both runtime and apply validators. Exact top-level fields: version=1, importedAt (ISO date), sources (ID-keyed metadata), metrics (definitions), weapons (array), attachments (array), communityStats (weapon-keyed map), patches (array), patchHistory (array). Maximum256 sources,64 metrics,256 weapons,2000 attachments,10000 patch observations,1000 correction-history entries. Slugs match [a-z0-9]+(-[a-z0-9]+)*, length<=100. Existing mw4:<slug> native IDs retained. External text<=500 chars per value, finite numbers only, URLs HTTPS without credentials. Source records retain exact fixed original URL, upstream URLs and mode/status/date. No artwork/long provider descriptions.

Weapons retain official basic values (number|null), supported slots, Apex name/blocked slots and separately labelled MP unlock reports; never infer DMZ unlock. Attachment IDs from the structured provider are stable, standard and Apex records are separate kind fields; compatibility references existing weapon slugs, effects reference existing metric IDs and compatible weapons. Provider multipliers are numeric>=0, explicitly operation=multiply and community-unverified/uncertain-mode. Missing effects stay absent, not multiplier1. Source-provided labels cannot create a new unit conversion. Raw nonphysical units remain literal. Every official numeric observation has value, unit and applicability=reported|unknown|not-applicable. Only reported permits a finite number; unknown and not-applicable require null and have distinct displayed labels. Melee fire-rate, magazine and reserve are not-applicable; missing firearm values are unknown. Null is never zero. No inferred aliases or fuzzy merging. Conflicting identity/compatibility is rejected for review, not overwritten.

Native pack data is populated once through reviewed collection; subsequent patch apply modifies only patches and patchHistory. Everything else is retained byte-semantically in parsed JSON, including owner-edited weapon/attachment/base fields. Raw provider content is kept only in ignored .local captures. Patch observations are separate source reports, never a mutation of unknown-mode baseline statistics. Corrections to a patch observation retain its previous value in patchHistory with previous hash and replacement ID. No silent history truncation: capacity exceeded rejects apply.

## Fetch/discovery

Read-only network: HTTPS exact host www.callofduty.com, no credentials/ports/query/fragment; redirects rejected. Index is exactly /patchnotes; pinned rolling URL is /patchnotes/2026/10/call-of-duty-modern-warfare-4-launch-patch-notes. Discovered paths must match /patchnotes/20[0-9]{2}/(0[1-9]|1[0-2])/call-of-duty-modern-warfare-4-[a-z0-9-]+, length<=300. Historical paths containing -beta- are excluded with an explicit warning from this launch-era check. Only anchors actually present in the official index qualify; sort/deduplicate URLs before fetch. Maximum12 articles (pinned included); exceeding cap fails with actionable error. Each response<=2MiB, aggregate<=16MiB, timeout12seconds per request and120seconds total checked during chunk reads. HTTPS text/html only for notes/index; population JSON uses only https://codloadout.gitlab.io/data/mw4-community-attachments.json and https://codloadout.gitlab.io/data/mw4-community-stats.json; official launch uses only https://www.callofduty.com/blog/2026/10/call-of-duty-modern-warfare-4-launch-multiplayer-operators-weapons-equipment-create-a-class, same byte/deadline bounds. Reject compressed/unexpected content and invalid UTF-8/JSON rather than execute it.

An article must identify Modern Warfare4 in its title/header and have a recognized dated section. Empty body, missing expected tables when weapon-adjustment headings exist, or malformed change rows fails that check; Qualitative paragraphs/bullets naming a known weapon are retained as source/date/mode review warnings even when structured tables exist; their prose is not normalized or copied into numerical observations. Other unsupported qualitative structures are explicit review warnings. A failed check writes no proposal/database. Unrecognized mode/weapon rows retain raw context as warnings and do not create applicable numeric observations. Missing previously seen pages/rows never deletes existing data; record warning. A fully parsed article without weapon changes is a successful zero-change check, distinct from a fetch/parser failure.

## Patch proposal v1

Fixed local output .local/weapon-patch-proposal.json,<=4MiB, exact fields: version=1, baseRevision (SHA256 of database bytes), articles (sorted unique allowed URLs), observations (<=5000 validated rows), warnings (<=1000 bounded strings). Event identity is SHA256 of canonical JSON tuple(sourceURL,date,mode,weaponSlug,variant,metric); ordering is not identity. Variants require an exact canonical weapon identity and a known compatible attachment name, exact full Apex name or exact canonical weapon-prefix-stripped Apex name. The four reviewed short publisher aliases are Hyperburst (Hyeon Burst), Sentinel (Oden), Assault (Type73), Void (X-58 Nyx); Warlord 12G Slug Rounds is a reviewed alias for its reported slug ammunition. Arbitrary suffixes/prefixes never qualify. Fields include ID, sourceURL/date/mode, weaponSlug, variant, metric, before/after raw strings, unit=unspecified unless explicit, status=official-reported. Raw row text stays bounded, not treated as numeric/unit evidence. Corrections with same identity replace the current row only after preview and retain prior report in history. Identical observations are no-ops, including after earlier apply; conflicting duplicates in one proposal reject. Unknown top-level/row fields reject. Apply validates every article/source URL, ID recomputation, shape/bounds and existing weapon references, not just a supplied checksum. A local proposal is explicit user-selected input, not cryptographically authenticated publisher evidence; editing it can propose a false report, so review/source links remain necessary. It cannot execute code, change paths or mutate base records.

## Apply and recovery

All write paths are fixed below verified root: content/weapon-intel.json and .local/weapon-updates/{writer.lock,backup.json}. Refuse symlinks/reparse-link paths and nonregular existing files on all components. Acquire exclusive create lock, then reread database and compare full-byte revision. Reapplying identical events succeeds no-op even if the original baseRevision is old; any actual additions/corrections require exact matching baseRevision. Preserve unrelated reports and all base records. Validate entire result and all limits before writes. Under lock, first atomically replace backup.json with exact previous database bytes, then write a unique same-directory temp database and os.replace it. Fsync file before replacement. Failure before database replace retains old database; after replace it contains the whole valid new JSON. Backup remains the prior valid state; no automatic recovery overwrite. Lock always removed on normal error/success; a process crash may leave lock, which blocks writers and directs owner to inspect/remove it after confirming no writer is alive. A backup temp failure never proceeds to database replacement. No recursive deletion, no user-controlled output/root on the CLI. Library root injection is tests-only for disposable directories.

Checks never fetch automatically during npm test/build/check. npm run weapons:check explicitly stages; --fail-on-new returns2 for a valid proposal with additions/corrections,1 for errors,0 for no changes. npm run weapons:apply explicitly applies the fixed staged proposal; build separately refreshes static pages. Output explains this boundary and counts; no false current-live-build label.
