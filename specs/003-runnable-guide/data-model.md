# 003 data model
The foundation contract in 001 remains conceptual authority. Exact schema and seed are being reviewed with the content specialist before code starts.
Pack: schemaVersion, stable id/contentVersion, game/mode/build scope, sources, items, recipes, objectives, guides, maps, locations, claims, assets. Sources include type/reviewedAt; records include status/sourceIds. Fixture packs cannot cross-reference real packs. IDs are stable safe namespaced lowercase slugs.
Item kind: item/weapon/currency/resource; numeric stats nullable with metric/unit, build/mode/context and per-field verification. Recipe ingredientsKnown and eligibility do not silently infer input-pool semantics. Costs are consumed/retained; objective effects never become craft outputs. Claims permit unresolved conflicts.
Profile v1: id, revision, packId, contentVersion, inventory and reserves dictionaries of bounded integer quantities; goals ordered references; completion dictionary of unknown/locked/unlocked/completed; spoiler choice; unresolved references preserved. Transactions require expected revision. Export is a bounded private backup, never a content pack.

Canonical profile caps: 1 MiB UTF-8, depth12, 20,000 nodes/keys total, 100 goals, max10,000 entries per quantity/progress dictionary, max2,000 string length. Dangerous object keys rejected recursively before semantic use. Atomic restore retains previous profile. Content mismatch requires previewed explicit rebind; retired IDs stay recoverable. One-goal recipe rounds target/yield upward; retained requirements use max not sum per batch. Unknown eligibility is blocked, never inferred from output destination. Currency is an independent typed item ledger.
