Status: implemented and verified; final independent receipt tracked in checklists/requirements.md. Authorized2026-11-01: implement all six recommended areas.

FR001 Compare2-4 weapons with explicit shared-launch, community-Multiplayer or private-DMZ views. Match metric units and show source/build/date and unknown values. No mixed-mode ranking, fabricated damage/TTK or exact combined predictions.
FR002 Build compatible loadouts, max5standard plus1Apex planning template, one per slot, enforce reported weapon slots/compatibility and Apex blocked slots. Do not model looted eight-slot instances. Save/load/rename/delete<=100 named builds privately; export/import one build with explicit preview, preserving unsupported-game/version rejection. No automatic removal of conflicting choices or upload. Inspect each selected attachment's sourced benefits/tradeoffs; aggregate stat predictions remain unavailable until verified stacking exists.
FR003 Capture<=100 private observations: weapon, metric/unit, numeric value, mode, game build, date, target/armor/range, method, recorded/repeated status and optional normalized screenshot. They are user observations, never automatic official verification. Review, remove and export/restore private evidence; no public catalog writes. Raster limits/strict existing decoder deadline retained; SVG/executable images refused.
FR004 Provide an opt-in loopback update manager with browser controls for check, inspect exact additions/corrections/warnings, explicit apply and explicit backup rollback. Show current database revision, last check/result, source dates and backup availability. Bind apply to reviewed proposal hash and database revision; rollback requires current revision. Serialize actions, keep CAS/lock/atomic backup semantics, retain failed operation status, and reject cross-origin/unauthenticated writes. No auto-scheduler, arbitrary commands/URLs or public reader write API.
FR005 Provide source-backed plain-language attachment explanations, quantified benefit/tradeoff direction (duration sign clarified), unlock reports, compatibility and unknown effects. No invented acquisition/stat claims. Add per-weapon contextual builder links.
FR006 Track manual acquisition, owned attachment identities and named owned blueprints privately. Show honest known mission/guide/location references derived from existing records, plus official acquisition guide and generic map access when specific links are unknown. No invented drops/unlocks. Search/filter checklist and use saved tracker state in builder without preventing hypothetical planning.
FR007 All new destinations are discoverable in shared navigation and existing armory. Compact responsive/keyboard/dark-light/200%text UI, stable controls, explicit errors and native basic links. Private browser state has bounded validated JSON, transactional revision CAS, export/import preview and prior snapshot recovery. Failure/stale saves retain unsaved edits; no existing profile/catalog-schema migration.
FR008 Test rules, units/scope, adversarial imports, persistence/stale/error recovery, screenshot bounds, manager security/proposal binding/rollback failure, live no-change patch check, three-engine actual workflows/responsive layout, accessibility, full runtime and existing affected navigation. Independent review/converge, clean local build/preview. No public deployment or claim of verified current DMZ combat data.
