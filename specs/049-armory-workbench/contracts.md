# Contracts and limits

## Private workspace v1

New IndexedDB dmz-armory-local v1, workspace store, fixed key main. Exact value fields: version=1,revision(integer0..MAX_SAFE),builds(array<=100),observations(array<=100),acquisition(object keyed<=256knownweaponIDs). Builds exact id(UUID),name(1..100),weapon(knownslug),attachments(array<=6knownIDs),notes(<=1000),updatedAt(ISOdate). Structural workspace validation accepts bounded syntactically valid unknown/removed weapon, metric and attachment references so catalog changes cannot make the entire private workspace unreadable. Contextual legal-build checks are separate: the active builder/import preview reports missing IDs, compatibility, duplicate slots/5standard+1Apex and blocked slots. Saving an active build requires those checks; existing archived builds remain exportable/removable and do not block unrelated evidence/tracker saves. New observations enforce selected known metric/unit; archived observations preserve original metric/unit. Unknown acquisition keys/owned IDs remain retained and visibly labelled archived, never silently discarded.

Observation exact id(UUID),weapon,metric(known metric or official field),value(finite0..1e9),unit(exact selected metric unit, raw unspecified retained),mode(dmz|multiplayer),build(1..120),date(ISO),target(1..100),armor(<=100),rangeMeters(null|0..10000),method(1..1000),firingMode(1..100),loadoutContext(1..1000),status(recorded|repeated),image(null|{base64,mime=image/png,width,height,sha256}). Max image2MiB, max2048axis/4194304pixels, total images8MiB, total serialized workspace12MiB; maxdepth16/20000nodes, plain inert fields only. Original screenshots normalized/reencoded via unchanged five-second decoder with metadata stripped. Restores strictly decode/validate image stream and hash before preview/save; imageInfo signature/dimensions alone cannot approve images. Imported text never rendered as HTML. No SVG, remote URL or image upload. Evidence stays private and cannot label a community statistic verified.

Acquisition entry exact manual(boolean),attachments(unique array<=2000known compatible IDs),blueprints(unique names<=100, each1..100 chars). No implied unlock calculation from these checkboxes. References only existing sourced native records; generic source/map links are labelled when weapon-specific location is unknown.

All mutations commit whole validated next value in one IndexedDB transaction with expectedrevision; retain one previous valid snapshot in same record. Current tab serializes writes and updates UI only on transaction completion. Stale/quota/storage errors keep the failed candidate for export and block further mutations until explicit retry or reload; retry retains the original expected revision. Live form drafts can also be exported. Workspace backup format {format=dmz-armory-backup,version=1,workspace}; max12MiB plus envelope overhead64KiB. Restore preparation captures the current workspace revision and UI draft generation before decoding. Each image retains its strict5s deadline; a20s aggregate AbortController deadline bounds all restore-image work. Cancel/new selection/pagehide aborts and increments generation; late work cannot publish a preview or save. Preview shows counts and requires explicit Apply bound to that exact captured revision/generation. Any local draft input or mutation invalidates the preview; another-tab IndexedDB CAS conflict rejects Apply. Assign the next revision from that checked expected/current pair, never an imported revision or silently reread newer revision. Keep previous workspace and unsaved candidate for export after error. Single-build share {format=dmz-armory-build,version=1,build},max16KiB, excludes screenshots/acquisition; preview then use as draft/save under local ID. No clipboard/server upload required.

## Private comparison context

DMZ mode requires an explicit observation ID selection for each selected weapon and the chosen metric; no automatic latest selection or averaging. A numeric comparison is available only when all selections match exactly on metric,unit,mode,build,date,target,armor,rangeMeters,method,firingMode,loadoutContext after bounded input trimming. Weapon ID is the comparison dimension. Missing or conflicting context produces a no-comparison warning and separate evidence details, never a winner/ranking or mixed-context row. All observations remain user-reported regardless of repeated status; no actual in-game tests are claimed. Shared launch/community views retain their respective source dates/modes; no derived total build stats.

## Local manager

Bind exactly127.0.0.1; default4176, test port0, explicit CLI --port permits1..65535 with no fallback. Exact Host matching, no credentials/query/traversal paths, reject non-local socket/Origin and unsafe Sec-Fetch-Site. Root HTML may be opened through explicit top-level document navigation from the reader; APIs remain strict. GET session/state only same-origin/none; POST requires exact Origin, current cryptorandom32-byte session token, JSON contenttype/noencoding, <=4096bytes/depth4, exact action-specific keys. Session expires12h; no CORS, CSPself, frame-ancestors/object/base none, nosniff/no-referrer/no-store. Static allowlist only manager HTML/JS/CSS and required shared theme/navigation assets; no arbitrary file serving. Mutations single active job; 409busy, stale409, validation422; no retries that can replay writes.

Fixed actions: check (supervised Python check,timeout130s,stdout<=4MiB), apply(reviewedproposalHash64hex,Python --proposal-hash binding under writer lock,timeout30s), rollback(expectedDBrevision64hex,Python rollback --expected-revision under lock,timeout30s), build(fixed Node scripts/build.mjs,timeout120s). No shell, credentials, owner-supplied URL/command/root/output. Timeout kills only owned child; apply/rollback always use Python validated whole-file/lock/backup semantics; interrupted lock blocks later writes and prompts inspection. Status/proposal/state reads bounded (database8MiB/proposal4MiB/backup8MiB). Responses show public report metadata, never private evidence or arbitrary stdout paths.

Manager serializes check/apply/build/rollback. Apply verifies exact current proposal hash under Python lock, not just UI-side; external CLI change between review and action rejects. Rollback validates backup and currentrevision, then atomically retains the rollback target at fixed .local/weapon-updates/rollback-target.json (<=8MiB) before writing .local/weapon-updates/rollback-pending.json (<=4096bytes; exact version=1,beforeHash,targetHash64hex). Only then write current-as-backup and atomically restore target. Thus failure/crash after backup replacement still preserves the target plus current database; no target state exists only in memory. Reread currenthash before replace; preserve external owner edits.

On startup pending journal is exposed and other mutations blocked, never treated as success. Explicit rollback action resumes only after validating candidate and journal hashes and a current expectedrevision: current must equal journal.beforeHash (retry restore) or journal.targetHash (complete prior successful replace without replay). Any other currenthash refuses recovery pending manual inspection. Completion removes pending journal only after target promotion, then candidate; an orphan candidate before intent is safe/not a success and can be replaced only by a newly reviewed rollback. Abrupt crash may leave writer.lock; no automatic lock takeover. Missing/invalid/stale/locked/candidate-hash failures preserve files. Paths use048 safe-path/symlink checks; Node reads journal/status bounded and never interprets them as paths. Backup plus candidate plus current are each capped8MiB; journal4096bytes. Test failures at each boundary, including crash after backup replacement. No automatic recovery overwrite. Record last operation/result time at fixed ignored .local/weapon-updates/manager-status.json via safe atomic writes; stale crash-running status is identified at next startup, not reported success. Completion errors do not falsely report database unchanged if a child may have committed before timeout; show inspect-state requirement.

No network on startup/build/test or private reader. Check only contacts the previous048 explicit fixed allowlist, deadlines/caps unchanged. No automatic numerical baseline overwrite or screen evidence publication.
