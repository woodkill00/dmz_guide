# Feature Specification: Match operations
Created2026-10-30. Branch feat/035-match-operations. Status: locally implemented and synthetically verified; external gameplay checks pending.
Input: implement all seven recommendations following034: real-game verification workflow, full-match checklist, session journal, direct route editing/comparison, source-update impact review, workspace-wide search and backup management.
## User journeys
US1(P1) Trace missing roads with the existing editor and record dated private road/junction/bridge/gate reports bound to the exact network. Run a complete match checklist and record issues, without claiming automated gameplay observations.
US2(P1) Start a dated journal session with chosen routes/missions, record notes/observations and mission progress, retain temporary marks at end and optionally promote selected marks to owned POIs. Reload/resume/end/review/export; no live tracking.
US3(P1) Explicitly enable manual-stop map dragging, insert a map-picked stop after a chosen stop, duplicate a route and compare alternatives using their routing modes. Website locations remain protected; replacing a reference with a manual route point is an explicit confirmation, never provider-data editing.
US4(P1) Review source-update effects on routes/missions/collections/tracking and historical sessions. Rebind one current reference explicitly; reset obsolete reached tokens; missing records stay unresolved and history never silently moves.
US5(P2) Search POIs, routes, missions, collections, notes and sessions together and open the exact item/editor or actual map location.
US6(P1) See recorded last backup download, follow a restore walkthrough and compare incoming backup additions/changes/removals before existing guarded replacement. Cancel leaves data unchanged.
## Functional requirements
FR001 Road verification editor links to existing tracing tools, records graphSHA256/edgeID,kind,date,status(unverified/uncertain/passable/blocked),notes and explicit owner-gameplay attestation for passable/blocked. <=1000reports, notes<=2000; changed graph reports visibly stale and do not recolor/rewrite a different network. No fabricated road coverage, bridges/gates or gameplay tests.
FR002 Complete-match checklist covers choose objectives,build route,inspect gaps,follow/reach stops,add POI/evidence,record road issue,review session and save backup. Each saved session stores manual not-tested/pass/fail results and notes; failures are issues, never auto-marked passed. Include an exportable practical worksheet and honest external-evidence boundary.
FR003 Up to20 dated sessions, at most1active. Each stores <=10route snapshots (reference/manual waypoints only), <=64 owner-authored objective snapshots, <=100 captured manual marks, <=100 observation/note entries (text<=2000, optional capture-bound location), summary<=4000 and checklist<=10. Start/resume/end/edit notes/delete/export; keep frozen start objective snapshot and separately capture endObjectives/missingMissionIds at end; preserve historical route/identity. End offers promoting selected marks as owned POIs in same transaction, then clears only captured temporary marks after success. Repeated end/promote cannot duplicate. Private backups include sessions; public view links/selection packs exclude them.
FR004 Route dragging off by default. Only manual active-route stops draggable; stale revision/route switch/draft/bounds errors restore saved geometry. Moving stop clears its reached token. Source stops require explicit replace-with-manual confirmation; source data untouched. Popup insertion after stable token uses guard/revision/epoch, bounds and32stop limit. Duplicate route gets fresh ID, planning progress cleared, preferences copied safely. Alternatives compare direct/road mode, known distance in pixels, connectors/errors and unresolved stops; show both using existing overlays, no meters/ETA/safety or global optimum claim. Worker bounded10sec/latest generation cleanup.
FR005 Read-only impact summary before source update apply identifies changed stable records affecting routes/missions/collections/tracking/session history. Dedicated repair list paginated25 with exact target, changed/missing location state and explicit single-reference rebind using latest available record only. No mass retarget or lost provenance; obsolete progress removed. Tracking rebind archives exact prior observation in bounded history (1000), resets current confidence/date/evidence/visited/checked, marks revisit, retains favorite and requires explanatory confirmation; no old confirmed status transferred. Historical session references stay frozen and require retained source capture, no history rebind. Existing update authorization/download/preview/apply/recovery remains authoritative.
FR006 Workspace search includes available POIs(source/owned/reviewed), route names/stops, mission names/objectives, collection names/members, owned notes/tracking evidence, session notes/observations and road notes. Query<=256, bounded matching over admitted workspace, result pages50 with kind filter/reset; search runs on demand/debounced input, never every map pan. Exact edit/show targets retain identity and draft guards; unknown/stale positions disabled, all imported strings safe DOM. No source geometry/title copied into journal exports.
FR007 Backup page shows last recorded download honestly (not proof file saved), walkthrough and existing backup links. Existing private-restore preview displays paginated object diffs for added/changed/removed owned points,icons,routes,missions,collections,tracking,sessions/road reports and source/dependency changes; precise before/after summaries, aggregate counts, omission caveats. No mutation before existing explicit backup-before-replace gate. Strict20MiB decode/asset verification, dirty/epoch/CAS/quota guards preserved; no new remote service.
FR008 Optional FieldGuide.operations version1 only, strict exact keys/bounds/JSON, old backups admitted unchanged, references added to snapshot dependency pinning. Existing20MiB workspace/asset limits, transactional rollback, inert imports, browser-local privacy and recovery remain. Journal export contains owner text/manual coordinates and source handles only, no provider titles/coords/images. No distribution permission inferred; local commits only.
FR009 Help/docs and meaningful positive/negative unit/browser tests cover road staleness/attestation, journal reload/end/promotion/failures, dragging source protection/moved progress/insertion/duplicates/comparison, update impacts/rebind/history, exact search targets and read-only backup comparison. Run full map regressions,3engines/configured axe/320px and unchanged capacity budgets; independent definition/code/security/visual review, analyze/fix/converge. Real gameplay/physical device/screenreader validation remains pending until actual observations supplied.

## Assumptions and clarifications
User authorizes all seven recommendations. Existing partial road geometry is retained, not invented; road verification means tools/checklist for owner observations. Missions remain owner-authored. Route replacement changes only owned route stop. Journal captures selected live mission progress explicitly; historical entries are immutable references with editable owner notes, not automatically retargeted. Last recorded backup is advisory metadata. Local-only, no push/merge/deployment.

Clarified authoritative model: session route captures use {id,at,route} wrappers; objectives is the frozen start array, endObjectives is a separate end array (null while active), missingMissionIds explicitly reports unavailable missions. Operations.rebindings archives exact old tracking/reference identity before explicit repair; confidence/date/evidence/visited/checked reset, revisit set and favorite retained. See data-model.md for bounded fields.
