# Authoring boundary contract

## HTTP
The separate author CLI binds only 127.0.0.1, ignores HOST, and uses an explicit valid port (default 4174). Host must exactly match 127.0.0.1:<port>; malformed/duplicate or other hosts fail. No wildcard CORS, remote binding, cross-origin cookies, credentials, proxy trust or shell commands from HTTP input.

GET /api/session returns an ephemeral unpredictable token only through same-origin no-store JSON. State-changing requests require exact same-origin Origin and session token in a custom header, application/json content type, bounded body and no transfer-content confusion. Foreign/absent Origin and invalid/missing token fail before parsing/writing. GET endpoints expose only managed public metadata or approved assets, never filesystem browsing.

GET /api/catalog returns schema, current metadata snapshots and revisions, with no binary payloads or private player data. POST /api/save accepts packKey, expectedRevision, validated runtime pack and a bounded uploads array (assetId, category, base64). Base64 exists only in the transient request, never source records. The server resolves paths, repeats validation and returns saved revision/paths. Existing bytes must match metadata; new uploaded bytes must be normalized PNG validated through full pixel-stream validation. API errors have actionable code/message and no secret paths or file contents.

Media retrieval resolves pack and asset IDs through the canonical descriptor, never client-supplied paths. Git preview invokes fixed argv without shell, disables ext-diff/textconv/fsmonitor, bounds output, and limits paths to the exact serializer-managed catalog and media inventory. Unknown files and unrelated working-tree changes are never opened or displayed. There are no commit/push/reset/clean, arbitrary command or arbitrary file endpoints.

## Save and recovery
Serialize writers and acquire a fixed exclusive repository lock. Validate current snapshot and expected revision, complete candidate pack/references, rights, all asset bytes and all target paths before writing. For each target verify containment, case uniqueness, regular type and no symlink components. Stage bounded bytes/backups, flush files, publish journal, then apply known targets with expected-byte rechecks; publish final commit marker after all expected new bytes match. Never truncate an existing source file directly.

On failure or restart, only restore/finish targets matching recorded old/new hashes. A third-party edit stops recovery with a visible conflict and preserves recovery artifacts. No automatic deletion of a lock belonging to an unknown/live process. Document operator recovery and filesystem power-loss limits. Preserve unrelated working-tree files and edits. Migration uses the same bounded safety rules and single authoritative marker, never ambiguous canonical/legacy precedence.

## Contributor UX
Guided renderer is storage-independent. Studio does not import private profile initialization. Every change marks a draft; save freezes mutation; stale save preserves recoverable draft. Advanced JSON uses bounded parser and immutable identity validation. Media selection, crop, thumbnail and duplicate reuse change draft only until explicit save. Library pages at most 24 entries, loads image bytes only when previewed/visible, and shows usage. Delete preview blocks used references; cancellation never writes. Dirty navigation warns, retains or exports the draft.

## Resource profiles
Portable: 32 assets, 2 MiB each, 8 MiB total, 2048 pixels per dimension, 4,194,304 pixels per image and 16,777,216 pixels total. Published: same per-image bounds, 1,000 assets per pack, 1,024 per build and 256 MiB bytes total. Canonical metadata: global 8 MiB and 20,000 total entity records across the site; each generated runtime pack is also bounded to 8 MiB. New save upload batch: at most 8 MiB and 32 images, with a 20 MiB request envelope. Limits are shared constants and reflected in UI/schema/docs; they are tested separately.

## Precisely bounded guarantees
The writer coordinates Studio processes and compares hashes immediately before mutation; portable Node filesystems do not provide atomic compare-and-swap against an unrelated editor in the final check-to-rename window. Preserve before bytes and stop recovery on unknown bytes; do not claim protection from a malicious local process or hardware/filesystem failure. Single writer ownership is required while saving. New uploaded PNG accepts only a reviewed chunk allowlist (IHDR, PLTE, tRNS, IDAT, IEND and standard color-space chunks), rejecting hidden text/EXIF metadata. Normalization can increase photo size; show output bytes and resize/crop choices, preserve alpha, and never promise compression savings.

Thumbnails use a separate stable asset ID and their own generated asset directory, with source-only parentAssetId/variant metadata; runtime metadata stays ordinary image metadata. Existing ORIGIN.txt provenance is migrated explicitly, not discarded. Migration enumerates and removes only expected unchanged originals, never recursively deletes unknown files.

## Recovery operations and contributor controls
The lock records PID, process start marker and a random owner token. A live or unverifiable owner blocks new writers. An explicit `npm run author:recover` command may reclaim a confirmed dead local process lock only after reporting its transaction and validating the journal and current path hashes; never use lock age alone. Interrupted transactions are not silently discarded. The command supports preview first and an explicit apply flag; unexpected hashes stop and preserve backups. The normal author startup reports the recovery command and does not mutate a pending transaction automatically.

New catalog: the Studio provides New catalog, asks title, game/mode/build, content version and fictional/unknown status, generates a stable namespaced pack ID and collision-free pack key from the title (optional advanced ID override before first save), and validates an empty catalog before adding records. It writes nothing until Save. Portable import: choose file, bounded parse, decode/normalize media where needed, display pack identity, counts, changed records and rights issues; Apply replaces only the draft. Cancel preserves the previous draft and source. Existing target identity cannot silently change; import into a new catalog is explicit.

Pictures: choose active record, set Primary picture or Add additional picture (at most eight); show the selected IDs/preview and permit explicit removal. Crop uses integer x/y/width/height controls with full-image reset, numeric target maximum dimension and explicit Apply crop/resize. Default maximum dimension is the lesser of source size and 1024, never upscale; Keep original dimensions is an explicit option within 2048 bounds. Thumbnail is optional, longest side 256, preserves aspect and alpha, and is a separate draft asset with source-only parent relationship. Show before/after dimensions and byte size. If canvas encoding or size limit fails, retain the prior draft/image and offer smaller dimensions or cancel; no claim of guaranteed smaller PNG output.

Save failure: stale revision retains the draft, provides Download draft and Reload repository only after explicit discard confirmation; no silent retry. Expired session retains draft and offers reconnect/reload after export, never automatic mutation. Disk/recovery errors show safe error code, preserve draft, disable saves while recovery is pending and link documented local recovery steps. Busy controls are disabled while saving. Status is aria-live polite, errors are role alert with focusable summary, labels connect to controls, dialogs restore focus, drag/drop has file-input and numeric keyboard equivalents. Unsaved navigation and pack switching require explicit discard or cancel; no save on blur or back navigation.

Git execution is fixed arguments with `--no-ext-diff --no-textconv`, `-c core.fsmonitor=false`, `-c core.hooksPath=<empty trusted directory>`, literal pathspec semantics and no shell; environment disables optional locks/pagers and output is bounded. Only exact managed inventory paths are eligible. A bounded metadata-only changed-file summary is acceptable when Git is unavailable; no arbitrary file contents are read as a fallback.

## Saved-record preview
GET /preview?packKey=<key>&id=<record-ID> renders the validated saved source record with existing safe public detail markup. It is an author-only read endpoint, not a build/publish command. Its picture URLs use the validated lazy media endpoint and internal references resolve to other saved previews. The Studio offers a View saved preview link for the selected record and updates its source revision after successful Save. Opening/reloading the preview shows the latest saved source; unsaved drafts are clearly distinguished. Normal public dist remains unchanged until explicit build. No profile initialization, arbitrary HTML input, shell invocation or source write is part of preview.

The preview displays the saved catalog contentVersion and revision, not an unsaved draft. Missing/deleted records return a safe 404; invalid/duplicate query keys return 400. Text remains escaped and source links follow the existing safe-link policy. Internal record/image links are constructed only from validated catalog IDs. Per-call renderer options avoid mutable shared manifest state across concurrent preview requests. Cancel does not change preview because it never writes source.

## Completed backup retention
The 64 MiB transaction cap is not a lifetime retained-storage limit. Completed before/after backups remain until an operator safely archives them while all writers are stopped and recovery reports no pending transaction or lock. docs/content-studio.md defines the non-destructive archive and unchanged-receipt restoration procedure. Git history review is capped at 1,000 receipts and 8 MiB total receipt bytes, with visible truncation; ordinary Git tools remain authoritative for full review. There is no automatic pruning or destructive cleanup endpoint.

## Cooperative read consistency
Catalog reads, selected-media reads and managed-change summaries share a process-local reader/writer barrier with saves. Reads may run concurrently; a writer waits for earlier readers, and later readers wait behind that writer. A read begun during an in-progress cooperating transaction waits for its completed snapshot rather than observing a partially installed journal. This does not remove external-editor/hash validation or claim cross-process atomic filesystem snapshots; unrelated external modifications still fail closed when detected.
