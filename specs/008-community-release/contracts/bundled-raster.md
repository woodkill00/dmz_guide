## Bundled raster API
Source: content/assets/<pack.id.replace(':','_')>/<asset.path>; portable schema paths remain assets/<safe-name>.png|jpg|jpeg|webp. Generated manifest /assets/content/bundled-assets.json uses exact shape {format:'dmz-bundled-assets',version:1,packs:[{packId,contentVersion,assets:[{assetId,path,mime,sha256,bytes,width,height,url}]}]}. URL is /assets/bundled/<safe-pack>/<sha256>.<png|jpg|webp> derived from MIME, never an imported URL. Max manifest1MiB,32 packs,1024 entries,8MiB aggregate bytes and16M aggregate pixels. Duplicate pack/asset IDs and case-colliding source paths are invalid. Manifest metadata must exactly match the active pack before selected asset fetch. HTTP redirects/external origins/unsupported MIME are rejected. Browser fetch streams into a declared-byte cap, aborts after5seconds, and validates actual hash/header/decode before returning portable [{assetId,base64}] payloads. No persistent/global cache masks later content-version changes.
Build API prepareBundledAssets({root,packs,schema}) -> {manifest,files}; writeBundledAssets({dist,manifest,files}) writes only prepared copies. Browser API loadBundledManifest(options), bundledAssetURL(pack,assetId,manifest), loadBundledPayloads(pack,{manifest,assetIds,decodeRaster,signal,fetchImpl,baseURL}), decodeBundledRaster(bytes,mime,signal). Optional assetIds enables one-image map/reader loading; omit for complete editor/export bytes. Empty pack assets do not require a fetch. Public prerendered image markup remains available with JavaScript and IndexedDB disabled. Fixture rights identify original programmatic artwork rather than game evidence.
Manifest parsing additionally limits depth8,20000 nodes and1000-character strings/keys, rejects duplicate/pollution keys, requires integer version1 and exact allowed keys. Each response and actual decode has a5-second timeout; caller cancellation cancels streamed reads/decode. Build checks every source ancestor including repository root and content/assets, rejects all symlinks and nonregular inputs, and checks actual bounded bytes rather than trusting filesystem size. Missing declared source pixels always fail public build; browser reference-only/missing/mismatched fallback remains readable and does not display stale bundled pixels. Static picture markup stays within the existing spoiler disclosure and uses a generic label when hidden. Public-content copy uses an explicit pack/site/validated-raster whitelist, not recursive content copy. Cross-pack same path filenames are legal and isolated by injective pack keys; case-colliding paths within a pack are rejected. Filename extension must agree with raster MIME (jpg/jpeg aliases accepted and generated as jpg).
Build verification is structural/integrity verification, not a complete JPEG/WebP/PNG codec decode. Full compressed-pixel validity is established by actual browser decode/smoke; malformed compressed bytes must fail runtime decode with a readable fallback. Public static images retain meaningful generic alt text and nearby rights/fallback context if a browser codec cannot display them. No extra codec or system-browser build dependency is introduced.

### Cross-surface spoiler compatibility
Maps and locations accept an optional boolean `spoiler` in schema version 1; absent remains false, so existing packs require no migration. Hidden maps and their locations are omitted from browser map selection, marker/list counts, coordinates, imagery and search until the user's local reveal preference is enabled. Non-spoiler prose and source labels use the same bounded cross-record spoiler projection. Raw JSON and the explicit authoring editor remain readable authoring inputs, not encrypted secrets.

### PNG pixel-stream boundary
PNG publication, portable editor decoding and bundled fallback validation additionally verify every PNG chunk CRC and the zlib stream using bounded native decompression. Inflated bytes are checked incrementally, never accumulated: exact IHDR color/bit-depth scanline geometry (including Adam7), row filters 0–4 and exact terminal length are required. Invalid compressed PNG streams fail before bitmap creation; valid PNG and other accepted raster formats still require actual bitmap decoding and matching dimensions. Shared preflight plus bitmap work has one five-second deadline and cancellation cleanup. Missing required browser decompression/bitmap capabilities produce a visible unsupported/error state, never an invented validation success. Hosted Chrome, Firefox and WebKit are the target compatibility evidence; physical-device certification is not claimed.
