# Refined upgrades and inventory
Created2026-10-31. Status: planning only; no production implementation authorized by this planning request.

## Journeys
US1 Find any item in the selected catalog, read/edit owned and reserve quantities in a compact list, see relevant shortages, then explicitly Save or Cancel without losing other draft entries.
US2 Open a dedicated Upgrades view, scan known requirements and manual completion, inspect one upgrade's details, and choose Track, status-only correction or separately confirmed purchase recording.
US3 Follow an upgrade requirement to the exact item and its known unfinished uses; keep context and return without losing edits. Browse the all-item directory separately from private inventory.

## Requirements
FR001 Compact semantic desktop rows and mobile two-line rows. Default compact, optional comfortable density,14–16px body text,44px action targets, full names available without hover. Stable row IDs, focus, scroll and column geometry during editing/save/filtering. Long names wrap rather than becoming inaccessible ellipses.
FR002 Inventory default shows all selected-catalog items, existing50-row pagination. Sticky headers/filter toolbar, name/category/ID search, category/unit-aware groups, All/Owned-or-reserved/Needed/Not entered/Missing filters and explicit sorts. Pack identity always visible; never combine private stock across catalogs. Preserve existing filters and add only validated derived modes.
FR003 Row fields: item/name+unit, Owned, Reserve, Needed by selected plan scope, Missing, Details. Available quantity and reasons in expansion. Inline quantity input/optionalsteppers edit existing draft only, explicit Save/Cancel. Blank-owned means Not entered, never zero; steppers disabled until a quantity is explicitly entered. Zero is distinct. Reserves never auto-clamped or spent, including reserve>owned. Keep raw invalid/offpage drafts and reveal exact invalid field on Save.
FR004 Dedicated /upgrades/ route reuses progression/upgrade controllers and the same profile/store, default DMZ-upgrade track. Keep /progression/ compatibility and distinct Orders/story/campaign namespaces. Main menu/Sitemap list Upgrades beside Inventory/Progress. Authored group/tier order only where present; otherwise preserve source order and name, never infer game order/tier from strings.
FR005 Upgrade rows show name/tier where authored, manual completion, known-requirement coverage and current blocker, Track and Details. Separate local completion from eligibility/readiness/spending. Unknown cost/gate/build state stays explicit; meeting all known materials is not full readiness. Cash and different units remain separate; no mixed-unit total. Existing domain engines determine every count/eligibility, not a second UI formula.
FR006 One explicit row expansion at a time shows requirements Owned/Reserve/Available/Required/Missing, kept-for contributors, source/build/evidence and links to exact private record. Existing confirmations remain independent actions: status-only never spends/refunds; purchase retains acknowledgment, full eligibility, snapshots, duplicate protection, CAS and recovery. No automatic purchase on check/goal/sort/quantity edit.
FR007 Slim header with catalog/search/useful filters and save status. Secondary source explanations, full spending history, import/reset/backup tools remain accessible below list or in details; critical conflicts, invalid data, unknown prices and version-mismatch warnings remain visible. Dirty save bar visible without covering rows/focus; screen-reader status announcements and text badges accompany color.
FR008 Existing profile versions, reserve/progress/source/spending history/backup/spoiler contracts preserved. No migration unless separately justified. Draft calculations clearly labelled and never enabled for purchase before Save; invalid quantities block derived advice instead of coercing NaN/blank to0. Keep/Search uses existing safe projection and shared-goal allocation to avoid double counting.
FR009 Align existing /items/ directory, Keep/Search and map entry-point visuals after core lists. Guide and map remain separate stores: link clearly, never imply automatic inventory/progress synchronization. No new scraping/game facts in this UI feature.
