# Refined upgrades and inventory
Created2026-10-31. Status: implemented and verified locally on 2026-10-31; automated gates and independent production review passed.

## Journeys
US1 Find any item in the selected catalog, read/edit owned and reserve quantities in a compact list, see relevant shortages, then explicitly Save or Cancel without losing other draft entries.
US2 Open a dedicated Upgrades view, scan known requirements and manual completion, inspect one upgrade's details, and choose Track, status-only correction or separately confirmed purchase recording.
US3 Follow an upgrade requirement to the exact item and its known unfinished uses; keep context and return without losing edits. Browse the all-item directory separately from private inventory.

Unknown cost/gate/build state stays explicit; meeting all known materials is not full readiness. Cash and different units remain separate; no mixed-unit total. Existing domain engines determine every count/eligibility, not a second UI formula.

FR009 Align existing /items/ directory, Keep/Search and map entry-point visuals after core lists. Guide and map remain separate stores: link clearly, never imply automatic inventory/progress synchronization. No new scraping/game facts in this UI feature.

FR010 Group items into collapsible sections using authored categories and unit/kind metadata. Materials/components/consumables/equipment/weapon parts/currencies appear only where catalog data supports them; uncategorized items stay in Other. One primary section per item, deterministic authored order, visible/total counts after spoiler projection, expand/collapse all, section filter/search. Collapse/filter never discards drafts or prevents invalid-field reveal. Currency/unit totals remain separate.
FR011 Four distinct relationship columns: Recipes = direct recipe inputs/required tools; Upgrade uses = direct dmz-upgrade requirements; Mission uses = explicit mission/order/story requirements with track labels (campaign separate/labelled, never merged completion); Crafts = output items of those directly linked recipes. Producing recipes for obtaining THIS item remain separate in Details. Unlock-only reports are not executable recipes/costs. No name matching, transitive assumptions, scrape-text guesses or cross-pack joins.
FR012 Each relationship cell shows a named exact-record link and an optional +N list of remaining unique visible references. Recipe IDs, upgrade/objective IDs and crafted output IDs deduplicate independently; multiple routes to one output do not duplicate that output. Role badges distinguish consumed, retained and unknown. Lists are catalog uses, not an allocation or count to spend. Completion badges distinguish known uses from unfinished personal needs. No recorded uses means no known links in this catalog, not safe to discard. Hidden targets/inputs/outputs must be filtered before names or counts are exposed; no hidden-count badge.
FR013 Wide desktop shows all four usage columns; medium/mobile condense them into one labelled Uses disclosure with all four full lists, without losing access or shrinking targets/text. Column preferences are view-only. Expanding related lists is deliberate; collapsed row targets remain conditional, including naturally taller long names. Related lists paged/bounded50; current-record/cycle/self references handled explicitly. Search/filter by category and usage type is read-only; direct navigation preserves dirty drafts and catalog identity.
