# Presentation contract
- Canonical identities: pack+recordID, existing profile revision/content binding. View state (density/filter/sort/page/expandedID) cannot alter quantities or completion.
- Owned blank=unknown;0=known empty; invalidrawstring remains recoverable. Reserve is independently editable and never silently reduced. Currency/non-count units keep identity/unit labels and separate totals.
- Input/stepper updates draft; Saved/Draft/Invalid visible. Save validates all rows, including filtered/offpage entries. Cancel restores committed values without changing spending history. No second IndexedDB write path.
- Required/Missing/keep-for/readiness derive from existing scoped domain engines. Unknown costs/gates/hidden dependencies cannot become a green ready badge. Spoiler projection runs before names/counts/previews are exposed.
- Details inline, maxoneexpanded row, close returns focus withoutscroll. Source evidence available on demand; criticalblocked/unknown/versionconflict remains in row/banner. Existing purchase/progress native dialogs keep the same confirmation/data-loss/privacy contracts.
- Stable keys,44px target controls, full readable names, optional density and both themes. Desktop table/mobile stacked row retains semantic label/header relationships. Table row shifts from intentional details expansion allowed; routine edits/save keep chosen control anchor.
- New /upgrades/ is an existing-profile view, not new completion/inventory storage. Sharednavigation and directpack-scoped links remain compatible; no private counts/notes in URLs.

## Grouping / relationship projection
Sections derive from admitted item category/kind/unit, one primary section plus Other fallback. Filtered50-row pagination remains bounded across groups. Collapse is view state only; save validation reveals and expands the exact invalid row before focus.

| Column | Direct catalog edge | Dedup key | Meaning |
|---|---|---|---|
| Recipes | recipe.inputs[].itemId equals this item | pack + recipe ID | Recipe using this item as consumed/retained/unknown-role input |
| Upgrade uses | dmz-upgrade objective.requirements[].itemId | pack + objective ID | Known upgrade requirement; completion shown separately |
| Mission uses | explicit typed mission/order/story requirement | pack + track + objective ID | Known required use with track badge; campaign not mixed |
| Crafts | output.itemId of directly linked input recipe | pack + output item ID | Item that can be produced through that linked recipe; not a claim of readiness |

Quantity/cost/role evidence stays with each reference. Do not sum relationship counts as item quantities or multiply material needs from link counts. Output direction is distinct from 'recipes producing the current item'. No arbitrary source-summary matching, unlock→recipe fabrication or automatic cross-pack identity merging. Cache stable index by pack/content version; visibility/completion projections are refreshed independently. Spoilers are filtered before all names/counts, including cached results. +N means additional visible unique references only. Incomplete/unrecorded use coverage cannot imply no gameplay use.
