# Data model
WorkspaceSaveReceipt v1: owner(profile|armory), key(bounded canonical ID), revision(safe positive integer), savedAt(ISO UTC). No item names/counts, screenshots, credentials or arbitrary strings. Metadata may be lost/forged and is never restore authority.
WorkspacePreferences v1: density(compact|comfortable), disclosure/open states bounded known IDs. Recent/pins reuse existing navigation state; no second route database.
QualityFinding: id stable encoded pack/record/field; binding string includes contentVersion and evidence code; type/title/field/message, readerURL and authorURL from admitted catalog identity. Only guarded public projections leave build. Local review state pending|later|checked tied to exact binding; changes are unreviewed. Checked is editorial, never modifies missing-field fact or player completion.
Saved-data preview: explicit requested owner/current-or-previous, validated raw payload remains memory-only until downloaded; manifest validates module kinds/hashes/size and omissions. Existing owner restore tools revalidate. No implicit restore or progress migration.

## Exact v1 metadata limits
Save receipt exact keys version,owner,key,revision,savedAt; version1; owner profile|armory; profile key matches^[A-Za-z0-9:._-]{1,100}$, armory key exactlymain; revision safeinteger1..MAX_SAFE_INTEGER; savedAt canonical ISO UTC24 chars and valid, not more than5minutes future or older than30days for live notifications. Serialized receipt<=1024bytes. No extra keys. One last metadata receipt in localStorage; local metadata cannot authorize a restore or prove a file exists. Transport is BroadcastChannel dmz-workspace-v1 with storage-event fallback; dedup byowner/key/revision/savedAt, max32memory keys; ignore receipts not newer than last-seen revision perowner/key, max16 tracked keys (drop oldest). Future/malformed/oversized messages ignored. Even well-shaped forged metadata is advisory only and never triggers reads/writes/reload automatically. Publisher catches all failures and cannot change successful transaction results.
UI prefs exact keys version,density,topics; version1, density compact|comfortable, topics unique allowed14topic IDs,max14, each<=40chars; JSON<=2048bytes. Invalid prefs default without modifying owner data. Workspace panel open state never restored to avoid obstruction; help topic expansion only.
Quality index projection max10000findings and2MiB serialized metadata; explicit eligible/indexed/limited counts. Each finding stable id<=800, packId/recordId<=100, field<=40, kind<=40, public title<=200, message<=240, bindingSHA25664hex, reader/editorURL<=2048 allowed sameorigin relative/directory destinations. No raw private/imported HTML. Max100 rendered rows.
Quality log payload exact keys version,entries; version1;<=2000entries/512KiB JSON, each exact id,binding,state where id<=800,binding64hex,state later|checked. DuplicateIDs rejected, unknown/disappeared IDs retained within bound but never counted current. Overcapacity rejects new review before write and retains prior serialized log. UI pending default; changed binding always pending with prior-state stale indication. Export log explicitly; imports preview matching/stale/unknown then require explicit apply, malformed imports retain old log.

Editorial save envelope: exact value/revision fields; value is the existing bounded v1 quality log; revision safeinteger>=1. Current-missing revision0. An explicit write atomically validates current envelope/log and compares expectedRevision before one put; stale writes abort, preserving candidate/old record. Read-only absence never opens a new DB. Legacy localStorage log may be read/exported and incorporated only on explicit Save. Bundle quality module uses validated log payload, owner restore /quality/; module count7 and existing20MiB part/32MiB total stay bounded.
