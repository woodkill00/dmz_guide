# Requirements review checklist

Reviewer-owned quality gate. These boxes are deliberately unchecked during planning; implementation task completion does not approve them.

- [ ] Every story is independently testable and has an observable outcome.
- [ ] Editorial status, player completion, source verification and content presence remain distinct in wording and data contracts.
- [ ] The initial 24 Orders slots are scoped to the existing Hajin model; Story Missions, chapter variants and X01 additions have no invented denominator.
- [ ] Every audit state transition, note, export and restore has a bounded validation and recovery rule.
- [ ] Spoiler notes remain private, and public/search projections are reviewed for disclosure.
- [ ] Cross-origin backup and map handoff claims match what browser security allows; omitted modules are reported.
- [ ] Each functional requirement maps to a task and an executable acceptance scenario.
- [ ] External content sources have attribution, applicability and rights review before ingestion.
- [ ] Release claims distinguish automated checks from actual gameplay and source verification.
