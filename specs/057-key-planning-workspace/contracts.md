## Async/draft lifecycle repair
Syntactically valid historical key/use IDs in stock, favorites, targets, packed and opened arrays survive load/export/restore even when absent from current catalog. They are archived/unavailable, never rejoined by name or silently removed. Wrong backup kind/version, malformed IDs, reserved prototype names and invalid structure are rejected; an unknown-but-valid ID alone is not foreign. Archived targets show unavailable and never gain guessed access/readiness or map links.

Client maintains private draft generation(epoch), saved revision, async preview/read token, saving/dirty/blocked/disposed flags. Every private edit immediately increments epoch and retains a validated candidate before asyncsave; saves serialize. A completed save updates savedrevision but only replaces fields when epoch stillmatches; otherwise newer draft is preserved and queued against newrevision. Failure leaves dirtycandidate, blocks furtherpersistentwrites and exposes draftexport+explicitreload. Pagehide/cancel increments tokens, cancels FileReader where possible and dropslatecallbacks, not validstate. Initial/manualstorage reads and backup parsing capture epoch+revision+requesttoken; stale completions can't replace newer drafts or previews. Restore Apply requires unchanged captured epoch+revision, explicitreplacementreview and no dirty/in-flight/blocked persistence; session restore requires deliberate export/discard/reload first. Cancel/reselect/neweredit invalidates priorpreview.

Filters do not discard/change draft. Internal navigation waits for owned saves; failed/dirty draft prevents silent appnavigation and offers Stay, exportdraft, explicitdiscard/reload. beforeunload protects unsaved/temporary state for browser/back/externaldeparture; pagehide tears down callbacks. Retry storage/session→saved transition requires explicit discard confirmation if any dirtytemporarywork; never autooverwrites existingunreadrecord withempty. Session-only edits remain exportable/dirty and visiblynotpersisted. No false save success on quota/stale/blocked/corrupt paths. Export completes before any requested export+discard transition; cancellation/failure leaves candidate intact. Manual Reload and previous-snapshot recovery use the same generation guards and deliberate replacement semantics.


Explicit damaged-record recovery may store the exact prior main record under workspace/quarantine within this same dedicated objectstore (noDBdeletion/otherstorewrites). User first exports rawrecovery record, previews a valid previoussnapshot or validbackup, then reviews Apply. Recovery transaction compares captured exact boundedserializedmain (<=2MiB) before writing, refuses if it became valid/newer, validates candidate, uses validpreviousrevision+1(or1ifnone), writesquarantine andnewmainatomically. Main stays exact{value,previous}; quarantine remains separatelyexportable and never evaluated/rebound. UI epoch/cancel/review guards apply; no automaticcorruptionoverwrite. Failedrecovery leaves damagedmain/candidate untouched.

Numeric/private editors retain invalid in-progress buffers separately, increment draft epoch and pause saves until valid; export/navigation/restore cannot silently drop those buffers. Valid edits immediately retain validated candidates. Backup serialization reserves envelope bytes within1MiB.

Quarantine retains append-only bounded history at its dedicated key (max8rawrecords/16MiB), preserving earlier recoveries rather than overwriting the sole prior copy. Invalid/full history failsclosed and remains exportable; no automatictrim/deletion. History+newmain share one atomictransaction.
