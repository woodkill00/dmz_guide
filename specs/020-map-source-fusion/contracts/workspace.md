# Workspace and adapter contract v1

These are local module contracts, not a deployed HTTP API. Implementation lives under `tools/hajin-map/src/workspace/`.

## Inputs and limits

Accept UTF-8 JSON snapshot/backup files with schemaVersion1; reject unknown schema versions, duplicate IDs, invalid references, dangerous object keys, nonfinite/out-of-range coordinates, unsafe paths and unsupported geometry. Imported permission fields are informational and cannot change trusted registry policy. No imported scripts, HTML, URLs, archive extraction or remote fetch. Validate byte limit before parsing, then all nesting/count/string limits before allocating derived structures.

Foundation validator details: reject unknown snapshot fields (including any imported permission upgrade). JSON tree limits are200,000 nodes,128 own keys/object and20,000 entries/array; arrays must have their ordinary prototype, indexed data properties and no extra/symbol/accessor properties. Schema snapshots use null for unknown build/floor/image digest/dimensions, UTC ISO timestamps, SHA256 hex image digests, point x/y within declared frame bounds, category paths up to8 nonempty labels, and up to32 upstream reference IDs/evidence entries per record. Evidence is `{note,url}` with optional URL represented by null or an HTTPS link without credentials; activity is `{state,observedAt}` where only observed-active requires a timestamp. These validate source claims without authorizing ingestion or accepting coordinate registration.

Limits: 4 provider sources; 100 categories and 5,000 records per source; 20,000 source records total across retained snapshots; 5,000 custom points; 5,000 canonical entities; 20 retained snapshots; 20,000 review decisions; JSON depth16; IDs128 chars; titles200; notes4,000; source snapshot2MiB; backup20MiB; 32 custom icons,2MiB input/icon,8MiB sanitized icon total. Icons input<=2048 per axis and4,194,304 pixels, decode5s, output<=256 per axis PNG. Reject animation (APNG/WebP animation) even if browser shows first frame. Asset references must resolve or be explicitly listed omitted; omitted resources cannot create plotted entities until restored/validated.

In addition to count limits, every commit must preflight the exact UTF-8 serialization of its mandatory private-backup projection, including base64, metadata, omission manifests and all custom records/icons: it must fit20MiB. This shared byte budget can stop admission before an individual count maximum. Capacity means the maximum state satisfying all limits jointly, not all count maxima simultaneously. Optional authorized source bytes may be omitted to fit, with dependency manifests; custom data cannot be dropped. Recheck projection on permission-policy changes and redact newly restricted values rather than blocking recovery. Current and previous logical states must each remain individually exportable; a backup exports one selected revision, not both.

At a cap, reject the new operation without eviction and offer export/prune preview. Pruning snapshots requires no references from current or previous state or decision history; pruning decision history is not supported in v1. Tell the user when a new workspace is needed rather than silently discarding evidence. Undo history is append-only within the decision cap; CRUD last-mutation undo uses previous valid revision, including icon references.

## Adapter staging

`capabilities(sourceId)` returns referenceOnly / authorizedFileImport / authorizedAutomation and permission evidence. All three new providers start referenceOnly. `stageSnapshot(file, sourceId, permissionEvidence)` requires trusted policy authorization, validates bytes and returns an immutable preview token bound to bytes, workspace revision, rights policy revision and parser version. `commitPreview(token, expectedRevision)` rechecks all bindings; expiration, changed policy or revision requires restaging. Source record key is the triple in data-model.md; normalized records never replace raw records.

The supported import file shape is `{schemaVersion:1, sourceId, snapshotId, capturedAt, sourceRevision, frame, applicability, categories:[{id,path}], records:[{id,categoryId,title,rawGeometry:{kind:'point',x,y},applicability,activityClaim,upstreamRefs,evidence}]}`. Source-specific exports require a separately reviewed parser; no real provider schema is assumed. Official019 schema compatibility requires an explicit adapter and keeps its policy unchanged. Synthetic fixtures use a clearly labelled test-only policy, unavailable in production registry.

## Registration

Canonical frame is Hajin coordinateVersion1 with x right, y down in [0,4096], rendered through existing normalized coordinates. If exact frame/image identity is proven, use an identity/scaling registration bound to the digest and frame metadata. Otherwise use affine transform from >=3 noncollinear fit anchors and >=2 independent held-out anchors distributed across map quadrants, with at least one near the crop edge. Reviewer records landmark evidence, provenance and approval. Reject singular transforms, swapped/inverted axes unless intentionally declared, invalid extent/crop, points outside canonical bounds, max held-out residual>16 canonical pixels or RMS>8 pixels. These are display alignment tolerances, not game accuracy or meters. The UI reports residuals and prevents placement until accepted. Insufficient anchors or undocumented crop remains pending.

`stageBasemap(localFile, sourceId, permissionEvidence)` requires trusted authorization, PNG/JPEG/WebP signature and bounded decode, rejects animation, strips metadata via reencode and binds its digest to the coordinate frame. Limits:4 backgrounds total including canonical reference;32MiB input and sanitized bytes per added background,8192 per axis,33,554,432 pixels,15s decode. Keep no original metadata. Background bytes live in a separate resource store under the same revision-checked transactions and are always omitted from JSON backups with explicit digest dependencies. Author-owned source files can be restored separately. This omission never removes custom points/icons.

Registration preview offers source and canonical landmark picking or numeric anchor entry side by side without assuming alignment. After registration acceptance, switching backgrounds preserves center/zoom; overlay uses a keyboard-labelled opacity slider0..100 and at most two active images. Affine rotation/shear requires canvas-rendered warping, not Leaflet rectangular imageOverlay stretching. Mask state and marker positions stay fixed in canonical coordinates across backgrounds. If an image is unavailable, fallback canonical view explains the missing dependency; no automatic external fetch. For sources without authorization, compare via external reference links only. Frame/digest changes invalidate both background placement and dependent source points until registration is reviewed again.

## Visibility algebra

A source record is visible iff its source master AND its category mask AND current search match are true, and registration/applicability permit placement. Unknown categories enter Unmapped. Source master toggle preserves masks; per-source Show all sets all masks true and master true, Hide all sets masks false (master unchanged); global Show/Hide all applies to sources, Reviewed and Custom. Clearing search restores mask-selected visibility. Mixed state is derived from category mask values; unavailable counts/status remain distinguishable from hidden. Source and Reviewed views may intentionally overlap; label raw versus canonical counts.

## Comparison and decisions

`suggest(snapshotIds, mappingVersions, registrationVersions)` builds a spatial index; candidate distance<=24 canonical pixels, matching normalized category and compatible applicability and point geometry. Known different builds/floors exclude candidates. Unknown build/floor yields manual-review-only candidates with an uncertainty flag, never an equality assertion. Stable ordering: canonical distance then sourceId/snapshotId/recordId. Exclude records from the same source snapshot as automatic duplicate candidates. Cap output at10,000 pairs and250,000 examined grid entries (including incompatible candidates), return truncated status and ask to narrow categories/area. Same upstream lineage cannot increase an independent-evidence count; unknown lineage displays unknown, never independent.

`acceptDecision(draft, expectedRevision)` requires each selected field to cite a raw record field or an authored value plus evidence; records alternatives, reviewer/time and registration versions. `refreshPreview` returns added/changed/missing raw records plus affected decision IDs; acceptance stages new snapshot, flags affected decisions stale, and never changes selected canonical fields. Stale accepted entities remain visible with a stale badge until reconfirmed or removed. `split` and `undo` append decisions and preserve evidence; reject invalid history references atomically.

## Icon and backup operations

`stageIcon(file, declaration, description)` validates actual bytes then bounded decoding and PNG reencode; `commitIcon` is revision-checked. Never persist original metadata or file paths. Decode cancellation/timeout leaves no blobs behind. `deleteIcon(id,replacementId?)` previews all affected references; no replacement means cancel when referenced. A missing icon renders a built-in fallback with a warning, never an arbitrary remote URL.

`exportPrivateBackup` includes custom records/icons, masks and rights-cleared curation metadata; include third-party snapshot bytes only when trusted policy explicitly allows private export. Otherwise emit omitted dependencies with IDs/digests/rights reasons, preserving blocked references as unplotted pending records. Apply rights filtering transitively to canonical field values, rejected alternatives, notes copied from sources, history payloads and evidence: restricted derived values are omitted too, retaining non-content IDs/digests and dependency reasons. Unknown origin stays restricted. Authored fields remain exportable only with an explicit owned/authorized declaration, never by relabelling copied values. Restored redacted canonical entities stay unplotted pending dependency restoration/review; authored custom points remain usable. Background rasters are always external dependencies. Restore is replace-workspace only, with preview, confirmation, downloadable current backup and previous-state recovery. No ambiguous merge mode. Preflight dependency graph and quota estimate; actual quota errors still roll back. An incomplete restore must display missing dependencies and retain all custom data; no completeness success message. Public/share export is unavailable, including derived canonical fields.

## Performance reference

Chromium desktop, 4 logical cores, 8GiB RAM, canonical local background already decoded, production build, offline synthetic maximum-capacity fixture; record hardware/browser in evidence. After one warm-up, measure20 toggle/search samples p95<=250ms and five comparison runs each<=2s using a worker or yielding chunks. A cap-hit/truncation is an explicit result, not a stalled UI. Mobile 360px is a functional/accessibility target, not the desktop timing reference.

Implementation timing records first paint separately from durable IndexedDB completion; controls update optimistically while revision-checked preparation runs in a bounded worker. A failed persistence operation keeps the unsaved draft and reports failure. The reference hardware target above remains a target: the recorded Windows run enforces four CPU cores and a512MiB renderer heap on a64GiB host, and does not certify physical8GiB devices.
