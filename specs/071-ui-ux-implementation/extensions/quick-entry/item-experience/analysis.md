# Design analysis and fixes

Review is an implementer architecture/layout review, not a claimed multi-agent roundtable or independent signoff.

Pass 1 findings: simply hiding the catalog block would remove catalog recovery and exports; shortening all statuses would conceal unsaved/failed writes; one unconditional header would hide fixture identity; a tab-only layout could hide errors or break deep links; changing source item categories could affect saved inventory.

Fixes: move existing nodes into a disclosure, preserve status text/ARIA and expose every nonhealthy state; retain explicit fixture/other-catalog labels; prefer standard fragment navigation with progressive disclosure; use display-only category normalization; reuse current write owners and stable IDs. Native/private projection and photo/edit actions are explicit dependencies.

Pass 2 findings: tracker pages already wrap controls, so adding another wrapper would nest menus; native and private item pages currently have different headers; global panel changes could damage map and weapon layouts; a permanent sticky side card can exceed mobile/zoom height.

Fixes: tracker and common layouts share compact wording without a second selection owner; scope future shell changes by item class, require native/private parity, and avoid touching specialized weapon/map layouts. Disable sticky behaviour on narrow/short or enlarged layouts. The immediate helper observes only metadata/status nodes rather than whole item tables.

No unresolved architecture blocker remains for the proposed slices. Visual preference remains a review topic, and implementation/performance/accessibility evidence for the full redesign is pending. Do not treat this planning conclusion as independent approval or a shipped redesign.
