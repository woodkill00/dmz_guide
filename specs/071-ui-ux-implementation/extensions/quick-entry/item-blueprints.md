# Item blueprint checklist

2026-11-08, feature071 / quick-entry extension. User requests an Inventory-row checkbox for possession of an item's crafting blueprint.

Requirements BP1: a named, keyboard/touch-operable Blueprint owned checkbox on items with a visible listed producing recipe; currency and items without a listed recipe show a non-action dash instead of inventing blueprint applicability. BP2: ownership joins the existing Inventory draft and explicit Save/Cancel/departure/CAS recovery lifecycle, survives filtering/paging/collapse, and never changes owned quantities or auto-completes missions/upgrades. BP3: export/import, previous snapshots, reset, content rebind and unresolved-reference preview preserve or explicitly clear the checklist appropriately. BP4: Collection recipe cards and craft previews display the same saved ownership record. Blueprint possession is separate from material sufficiency, station/input pool, recipe evidence and upgrade/access prerequisites; no unverified new blueprint gate or bypass. BP5: old profiles remain valid without migration, with bounded inert validation and tests including stale saves, multiple browser engines and responsive controls.

Contract: optional `itemBlueprints` on supported profile versions1/2/3; a plain map of existing-style record IDs (maximum100 chars, maximum10000 entries) to literal true only. Presence records the player's ownership claim. Missing/unchecking removes the flag; it does not assert a verified game lock. Absence of the entire field remains accepted for every historical profile. New profiles keep their original shape until tracking is used. No new catalog/game facts, weapons-acquisition merge, content version or schema-version bump. Existing byte/node bounds remain unchanged. Generic historical/retired IDs are retained and surfaced as unresolved, including a blueprint reference that resolves only to a non-item. Previous reader versions may not understand the additive field; all current import/export paths use the updated validator.

Plan/tasks: extend the central profile validator/reset/reference preview and profile-change summary; add raw checklist state/checkpoint to the existing inventory draft and row rendering; keep input/row identity while toggling and saving; render ownership labels alongside existing crafting checks; add domain backup/migration/craft preservation and real-browser save/restore/cancel/conflict/layout evidence. Shared contract changes are serialized in this checkout. No independent review/skill invocation is claimed.

Analysis: reusing completion[itemId] would violate objective-only planner references and conflate ownership with progression, so use the optional typed field. A standalone autosaving checkbox would accidentally persist other unsaved quantity edits, so stage both through the one Inventory Save. Source recipes do not currently declare which items strictly require blueprints; ownership is a player checklist and never manufactures recipe eligibility. Craft/undo must preserve unrelated blueprint metadata. Optional-field validation allows current readers to restore old backups and retains prior valid snapshots; no automatic rewrite/migration of real profiles.

Implementation and test evidence follow below. Reviewer-owned checklists remain untouched.

Implemented BP1–BP5 in the existing profile/draft/presentation owners. Checklist entries are optional true-only flags, staged and committed with the same quantity draft. Unchecking removes a flag; toggling on/off before any save restores a profile that originally had no checklist field. Full reset explicitly clears it; progress-only actions, crafting, undo, content rebind and recovery preserve unrelated ownership. Both profile and content-update impact previews include retired/non-item references, using precomputed item-ID sets to keep lookup linear. Crafting cards/previews display the ownership claim without manufacturing a new recipe requirement or bypass.
