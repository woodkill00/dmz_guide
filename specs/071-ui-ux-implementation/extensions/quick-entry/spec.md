# Specification: fast tracker pages

Planning proposal, 2026-11-08. Scope: compact Inventory, weapon acquisition, Upgrades and Needed views; shared presentation and safe state adapters. Excludes provider data imports, accounts, cloud sync, automatic purchases, X01 carried-inventory simulation and a framework rewrite. Preserve source uncertainty, all existing URLs, saves, backup/recovery and keyboard access.

- QE1: A shared local tracker navigator connects the four pages. Current section and selected catalog are explicit. Full site navigation remains reachable. Preserve pack/profile/query context where applicable; never pass a guide pack as an armory workspace identity.
- QE2: At 1440×900 and 1280×800, normal loaded pages show search plus at least six actionable compact inventory/weapon rows or three upgrade-family summaries without initial scrolling. Measure with normal state, not by hiding blocking recovery/error messages. Long data uses one main scroll owner; 320px, short-height and enlarged text use normal flow.
- QE3: Inventory defaults to named compact rows grouped by existing family/type metadata, alphabetical then rarity ordering options. Each row has icon/fallback, name, rarity text, minus, quantity, plus and need summary. An inline details disclosure exposes reserves, mission/upgrade/recipe uses and exact-record links. Unknown stock is blank, distinct from entered zero. Keyboard number entry, Tab and Enter work without per-item dialogs. Never intercept browser shortcuts or trap keyboard navigation. Currency retains its existing 2m bound and format confirmation; material limit stays 1m.
- QE4: Inventory edits stage in the existing raw draft, including incomplete/invalid numeric strings, across search/category/page changes. One compact in-flow Save changes/Discard bar appears when dirty; saving persists the whole draft once through existing validation and revision checks. No autosave mixed with a separate batch Save. Guard departure and context change. Invalid Save reveals and focuses the actual row. Saving/failure never remounts a focused input or loses other draft values. Save failure retains draft; Discard explicitly reverts all staged edits. Save success alone clears dirty state.
- QE5: Weapon tracking shows class-grouped named rows and explicit Manual found controls, acquired-attachment counts and blueprint counts. Manual changes reuse the armory store's current single-action commit/revision behavior with pending/error state; acquisition details use an inline disclosure. Manual ownership, attachment ownership, stored weapon quantity and build loadouts remain distinct. No new inventory profile field or guessed manual-to-catalog association. Weapon roster/detail/gunsmith views remain intact, including *WZ/untested-DMZ labels and unknown stats.
- QE6: Upgrades show one compact family summary with the lowest incomplete tier and its requirements; other tiers expand below it. Preserve Roman numeral ordering and reviewed ambiguous groups. Completed checkbox is explicit and reuses the current correction contract; no material deduction. Record purchase remains a separate confirmed action. Ready, blocked, completed and unknown are distinct. Editing a required material opens the same inventory draft adapter, clearly labelled global saved stock, not a second per-upgrade stock balance. Never silently commit an inventory draft when checking completion; resolve dirty edits before the separate upgrade action.
- QE7: Needed remains the explainable aggregate for unfinished upgrades, with total required, saved, reserved/available, remaining and next-tier demand available. Default compact columns show item, saved, remaining and usage; expand for full arithmetic/print alternatives. Covered numbers green, known shortages red, uncertain values amber, always with text labels. Inputs for alternative print routes remain separate from direct shortages. Preserve protected-stock allocation, unknown quantities and no automatic spending. Missions keep their existing separate planner semantics; do not pretend the upgrade-only budget aggregates missions.
- QE8: Search is global within the current page's full eligible catalog and can cross collapsed groups/pages. Clear filters, visible match count and category jump are reachable. Advanced evidence/source/reserve filters live in a disclosure; a nonzero active-filter count remains visible. Do not silently drop existing controls or change bulk scope. Retain the existing 50-row bounded inventory window; consider virtualization only after evidence and separate identity/focus design.
- QE9: No hover-only actions, invisible icon labels or toast-only errors. Compact desktop controls have adequate spacing and at least 24px targets; touch/comfortable mode uses 44px targets. Native labelled inputs, focus rings, semantic headers, polite save status, accessible expand controls, both themes and reduced motion. Sticky chrome must fit available height; disable it when it would obstruct content/keyboard. Use shared tokens, min/max/clamp/calc where useful rather than forcing calc on every property.
- QE10: Existing profile/armory backups load unchanged. Any newly required presentation preference is versioned separately from game progress, bounded and optional. Catalog update/rebind and recovery remain explicit. No new production data model is expected for phase one; any discovered migration requirement returns to design before implementation.

Acceptance journeys: enter ten quantities by keyboard and save/reload; repeatedly click a fixed +/- control without movement; filter while a draft is invalid and return intact; toggle a manual, reload, then inspect attachments without changing inventory; complete a tier and see next tier/Needed update after confirmed save; verify material availability never auto-completes a tier; simulate denied storage/stale revisions and retain draft/recovery; switch pages with dirty input and choose Stay/Save/Discard correctly.

Implementation decision QE6: Edit global stock delegates to the exact inventory item on the existing inventory page, with the same raw draft and Save/Discard protection, rather than mounting another writer in Upgrades. QE2 grouped upgrades use responsive family cards (three across at desktop), preserving a current-tier summary and expandable other tiers. This is the chosen implementation of the focused working view.
