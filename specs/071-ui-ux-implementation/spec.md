# Feature specification: fluid UI/UX implementation

**Branch:** `plan/071-ui-ux-implementation` · **Date:** 2026-11-05 · **Status:** pre-implementation planning. **Design baseline:** reviewed070 proposal/concept. This feature makes that direction executable; production implementation is explicitly not part of this turn.

User asks for a final stress roundtable and Spec Kit plan with tasks → read-only analysis → authorized task/artifact repairs → repeated analysis until no unresolved planning findings. Tests below are mandatory future implementation work. No production behavior is certified by a clean planning analysis.

## User scenarios and testing

### US1 — Find and resume work across the site (P1)
A reader uses the five hubs and consistent Search/Tools utilities without wrapped duplicate navigation hiding content. **Independent test:** native/no-JS Home→hub→directory→detail/Back, every registry entry accounted for, other services unavailable,320px/short height. Given a current hub, navigation shows its scope; when an unavailable companion is chosen, then existing truthful startup/help behavior appears rather than a fake open/sync. Modified clicks retain browser behavior.

### US2 — Use the map without obscuring terrain or losing work (P1)
A player switches Layers/Find/Route/detail, uses source bulk/category controls and manual tracking while staying oriented. **Independent test:** task→detail→Back restores clean view context; no camera change on selection; dirty edit guard; route next identity survives unrelated inspection; Safe runs retains its distinct behavior. Given insufficient height or enlarged text, when docking cannot fit, then explicit Map/Task fallback makes all controls reachable without overlapping regions. Given delayed Save and departure, later callbacks cannot revive discarded drafts or update a newer view.

### US3 — Read and progress through concise reference/FOB lists (P2)
A player works through keys, missions/story, upgrades, inventory/crafting and bosses using readable bounded lists and detail links. **Independent test:** each journey and calculations/counters/order matches baseline; unknown stays unknown; required columns, filters, groups and list Back context survive layout changes. Given pagination, a bulk action explicitly names all matching versus this page and never silently changes its scope.

### US4 — Compare and build weapons with evidence visible (P2)
A player opens roster→weapon→attachment/build→source/update detail. **Independent test:** *WZ/untested DMZ, build/version/source and unknown stats stay visible; numerical comparisons, existing build/patch review and private armory data are unchanged. Given incomplete evidence, interface shows missing/unknown rather than zero or simulated data.

### US5 — Edit, update and recover safely in each owning workspace (P2)
An author uses private editor, map POI/icon/image/geometry/background tools, Studio and source/weapon updates/backups with consistent feedback and exact transactional previews. **Independent test:** actual ownership/token/revision/file identity, safe import/SVG bounds, cancellation, failure/recovery, denied storage and separate origins behave as baseline. Given failed or unknown Save, departure cannot continue as though success occurred, and recovery remains accessible.

## Functional requirements

- **FR-001:** One canonical Home/Map/DMZ Guide/DMZ FOB/DMZ Weapons shell with contextual siblings, visible current scope and Search, bounded Tools/All features. Preserve every feature ID/URL/deep link/modified click and generated-detail route family; matrix records exact owners/fallbacks.
- **FR-002:** Share presentation without merging Guide4173, Map5175, Studio4174 or Manager4176 services/databases; preserve public/native no-JS reading, private/spoiler boundaries and honest unavailability. No new accounts/provider collection/framework rewrite.
- **FR-003:** Semantic dark/light tokens, readable14–16px operational scale, compact/comfortable spacing,44px primary touch goal and visible contrast/focus. Density/theme changes never change data/order/quantities; no blanket calc requirement.
- **FR-004:** Layout allocation uses intrinsic content and visual viewport height as well as width. Short-height/enlarged-text/keyboard fallback takes priority over docking. No unintended sibling overlap or document horizontal overflow; essential actions remain reachable through the intended scroll owner. Diagnostic rectangles include shell, task, route/status and actual terrain together.
- **FR-005:** Exactly one active map task/detail representation, one contextual task navigator and at most one genuine modal; nested confirmation is a modal step, not stacked dialogs. Inspection is nonmodal, editing modality explicit, background inert when modal, no hidden focusable copies. Closed/Peek/Half/Full/Map-only/Task-only rules are in contracts/layout.md.
- **FR-006:** Keep stable input/row identity during counters, filtering, feedback, resize/theme/density and validation. One main scrolling task body; reachable header/actions, no nested-cell scrollers or sticky focus obstruction.
- **FR-007:** First pending departure captures destination+origin+pack/profile/revision and is frozen while guarded. Save continues only on confirmed success and valid destination. Stay clears intent only; failure retains draft/recovery; noncancelable Save disables conflicting replacement/Discard but not truthful status/recovery. Modified-click new tabs do not depart current view.
- **FR-008:** Async callbacks have operation/generation/context ownership; late completion/failure may not overwrite another task, selection, draft, feedback or focus. Preserve existing commit/deadline/cancel protocol; unknown outcome never triggers blind replay or claimed rollback. UI slow/unknown handling is specified in contracts/lifecycle.md.
- **FR-009:** Route mutations validate `{routeId, expectedRevision, waypointToken}` inside the existing atomic mutation boundary. Route/status actions are independent of inspected marker; stale action refuses. Undo binds exact prior mutation and revision, not whichever route is now active.
- **FR-010:** Preserve current resolved-waypoint and write/draft guards for Mark reached and coordinate availability for Locate. Road solve failure alone never disables otherwise valid manual tracking. No automatic recenter on selection/reached, no invented road legs/live GPS; preserve road gaps and worker lifecycle.
- **FR-011:** Preserve combined/per-site/category visibility, bulk scope, mixed switches, inactive-snapshot masks, source links/duplicate evidence and location/name dedup semantics. Filtering/source changes invalidate stale selection, not saved route/domain progress.
- **FR-012:** Safe runs keeps `/safes.html`, distinct saved state/roads, spawn/manual start, subset selection, list-only search, order/optimization, source conflict/reload, exact key/grid access evidence/colors, partial roads and worker races. Main private roads never silently become Safe runs roads.
- **FR-013:** Public Search, map-location Find and private Workspace search have explicit scopes. Private notes/drafts/queries never enter public index/share URLs/history. Empty/no-match/limited/missing/protected/unknown-position states are distinct; results open the correct entity, and unknown positions do not offer misleading Locate.
- **FR-014:** Common bounded semantic directory/detail patterns retain permanent identity, native detail URLs, required columns, per-cell wrap and explicit bulk-page scope. No duplicate editable desktop/mobile DOM. Registry/generated family and column/state matrices are normative.
- **FR-015:** FOB preserves lowest unfinished tier, Roman/alphabetic grouping, owned/needed-next/needed-total, unfinished mission/upgrade/crafting allocation and labeled collection colors. Layout never changes allocation/domain calculations.
- **FR-016:** Missions/story retain exact requirements/pages/chapter context, spoiler controls, source uncertainty and manual progress; UI work makes no completeness claim about all24pages.
- **FR-017:** Keys retain key images/icons, map area/grid, prerequisite chains, exact source screenshots and private stash/trip controls; no fabricated coordinates/access rules.
- **FR-018:** Boss LT/Commander groups retain stable kill/tag counters/order, tags5+ milestone, Commander tag exceptions, direct pages and keyboard reorder alternatives.
- **FR-019:** Weapon roster/detail/attachments/builds retain *WZ/untested-DMZ, unknown≠zero, applicability/version/source labels, sourced updates and reviewed patch workflow.
- **FR-020:** Author/management adapters preserve existing exact preview/hash/token/revision/file identity, source/image/SVG bounds, reference-checked deletion, transactional activation, permitted cancellation and every backup/recovery owner. A common appearance cannot bypass domain guards.
- **FR-021:** Feedback uses one routine status and one visible aggregate issue summary per active workspace with links to distinct owner field/recovery/details; important errors persist and are not replaced by ready/success. Expanded error text scrolls within its owner. No unbounded notification stack, repeated full-body announcements or focus theft.
- **FR-022:** Presentation cache is memory-only LRU≤8task entries including active, detail within its originating entry; total serialized UTF-8≤64KiB, query≤256UTF-16 units, disclosure IDs≤128/current allowlist, at most one detail return frame. Reject invalid entries rather than truncate identities. Eviction affects clean view state only; no editor drafts/operations/recovery owned by cache. Context/capture invalidation never rolls back domain data.
- **FR-023:** Capture/restore stable invoking identity on deliberate Back/close, with surviving row/task-heading fallback; stale async work cannot steal newer user focus. Inactive controls are unmounted/hidden/inert without stranding focus. Modal initial/return focus, Escape, native links/no-JS and non-gesture action alternatives are tested.
- **FR-024:** Test both themes, reduced motion,320px reflow,200%text, actual browser zoom and virtual keyboard/short landscape as distinct evidence. Map/table2Dexceptions do not exempt controls/cell text. Do not claim root-font scaling proves zoom or axe proves certification.
- **FR-025:** Validate layout preferences with bounded parsing and usable fallback; retain original bytes/key for rollback. Introduce authoritative default-legacy surface configuration and explicit effective-variant/mounted identity as defined by contracts/rollout.md, never migrate domain schemas or replay saves. Previously supported presentation remains available until each slice is independently accepted.
- **FR-026:** Record baseline DOM/input/layout measurements and retain deterministic registry/fixture admission limits. Do not invent speedups or call unlimited catalogs complete. Bounded/paged lists precede optional virtualization; necessary old assertions/fixtures remain.
- **FR-027:** Every surfaced feature has empty/loading/partial/stale/unavailable/read-only/denied-storage/error/no-JS applicability, scope-specific Back and recovery link; contracts/workspaces.md and feature-coverage.md define them, not a generic success screen.
- **FR-028:** Planning read-only analysis reports and artifact repairs are separate steps with preserved findings/closure evidence. Production task checkboxes remain unchecked in this turn. Every slice needs implementation/regression/independent review/rollback evidence before default activation.

## Success criteria / measurable gates

- **SC-001:**100%of current77registry entries plus listed generated-detail/management families have an explicit migration owner/task/journey and retain allowlisted feature identity on activation; rebaseline if registry changes.
- **SC-002:** No unintended control/sibling intersection or documentElement.scrollWidth−documentElement.clientWidth>1CSSpx in declared layout states; focused control+ring remain visible/revealable. Visual-viewport clipping/reachability is measured separately using the coordinate rules in contracts/layout.md; pinch zoom is not document overflow. Report actual rectangles and exclude only documented modal/inert or equivalent-control geometry, never silently skip failures.
- **SC-003:** Every deliberate task/detail return preserves applicable clean query/group/scroll/focus, with documented stale/eviction fallback, and zero domain/draft/progress rollback. Delayed save/search/update/reorder/departure tests assert exact state and no stale focus/error writes.
- **SC-004:** All old domain/storage/import/source/route/worker fixtures retain meaning. New shell/map/list/authoring tests pass Chromium/Firefox/WebKit plus planned actual-zoom/keyboard/touch/screenreader manual gates with exact limitations recorded.
- **SC-005:** Proposed65%workspace-width map/70%exploration-height goals are diagnostics, not permission to squeeze controls. Height/keyboard fallback and reachability take precedence. Actual terrain, route and pane budgets are measured in one coordinate space.
- **SC-006:** Final pre-implementation analysis has zero unresolved findings and full FR/SC/task coverage; this certifies planning consistency only, not absence of future runtime bugs. Each production phase remains separately gated.

## Edge cases / non-goals

Stress cases include320×400,320×568,667×375,844×390, enlarged text, long translated labels, simultaneous source+route+save errors, final input under keyboard, repeated task/pack changes, BFCache/pagehide, quota/CAS/unknown saves, source deleting a selected result and reorder before Reached/Undo. The original planning deliverable did not authorize runtime implementation; the subsequent explicit “implement” instruction authorizes this feature’s implementation. Game data acquisition, service consolidation, new framework dependencies, account/authentication and production deployment remain outside this feature.
