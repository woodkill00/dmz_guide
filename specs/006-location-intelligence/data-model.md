# Data model
Reuse locked pack maps/locations/assets and private profiles without schema changes. Map extent is [minX,minY,maxX,maxY]; axis determines increasing y direction, corner origin must match declared direction; center is normalized from the declared extent and axis. coordinateVersion identifies calibration context. Location floor is coordinates.floor, with unknown fallback; category defaults to uncategorized. Coordinates missing/nonfinite/outside extent/inconsistent map transform remain list-only.

Client ephemeral state: mapId, floor (all or named), category (all or named), query, sourceId (all or named), coordinateVersion (all or named), goalOnly, selectedId, camera {x,y,size}. Pack/map/floor changes clear selection/camera. Other filters clear selection if excluded. Derived result has records and plottable subset with reasons; source URLs are displayed safely but not fetched. Raster URL lifetime ends on pack/map replacement and teardown.

Projection contract: x = 100*(location.x-minX)/(maxX-minX). For x-right-y-down, y = 100*(location.y-minY)/(maxY-minY); for x-right-y-up, y = 100*(maxY-location.y)/(maxY-minY). Allowed pairs: top-left/down, bottom-left/up, center/down, center/up. Center is descriptive of zero inside declared extent, not an instruction to add another offset. No x/y swap occurs. Other pairs/unknown metadata are unplottable. Out-of-bounds list-only is defensive rendering, not permission to import invalid data; canonical validation still rejects invalid extent/floor/coordinates.

Positive need mapping: include ledger IDs with missing > 0 or retainedMissing > 0 only if the matching pack item kind is not currency. Currency is not a loot pickup. Unknown item references are excluded. Existing itemIds remain required; source uncertainty is always shown. A retained tool shortage can relate to a declared location just like a consumed item shortage.
