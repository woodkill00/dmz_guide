# Editor tools contracts

Version1. Existing exact target schema and canonical Save/operation protocol unchanged. All tools APIs are local author only and require existing Host/Origin/token/session protections. No arbitrary path, command, executable, port or remote URL input. Strict exact-object validators and existing20MiB request limits apply.

## Recovery checkpoint

GET checkpoint for exact target returns checksum revision (64hex or null), timestamp and current+previous availability. POST {target,expectedRevision,writerId,value} validates PageRecovery and checkoutId=SHA256(resolved root), matching target and record ID; incomplete prose is allowed under existing recovery schema. CAS mismatch409 preserves both server/browser originals. Browser binds its generation/target and only submits captured snapshots; at most one disk writer/request at a time with latest queued generation. Never overwrite conflict automatically. Two versions retained under .author-state/page-checkpoints/<64hex>.json and <64hex>.previous.json. Atomic durable temp/fsync/rename under existing root lock; unknown/corrupt/future data retained and exportable, not auto-deleted. Delete requires exact observed revision and explicit UI confirmation. Browser recovery is separate and remains functional when disk checkpoint unavailable. API never writes a canonical record or sets a Save receipt.

## Revision history

Server captures before and after Recovery-shaped snapshots in the canonical Save transaction. Before snapshot added only if no existing history; after named by immutable operation ID. Snapshot envelope {version:1,id,target,createdAt,kind,value,referencedAssets}. ID32hex; kind before/after; stored as .author-state/page-history/<target64hex>/<id32hex>.json. No caller-supplied filesystem names. Each snapshot<=12MiB; max5 retained, evict oldest with exact expected bytes in the same file plan. Restore retrieves a snapshot, compares record/layout/source and applies to current draft only after explicit confirmation; current base/version and retained section-anchor rules remain in force. Eligible normalized custom PNG bytes are retained in uploads. Other source picture IDs are referenced and restoration must refuse missing library assets rather than silently dropping them. Snapshots never grant inventory or certification. Same-operation replay cannot append history twice. Automatic eviction is permitted only for the advertised five-snapshot retention limit, in the same canonical Save transaction. A separate manual prune action requires explicit confirmation; it cannot delete current canonical content.

## Capacity and safe storage

Checkpoints/history own directories only, strict finite filenames, no symlinks/devices, bounded traversal<=4096 files,256MiB combined active payload budget; no widening existing64MiB canonical transaction budget. All reads use existing safe-path checks/size bounds and validate stored envelopes. Existing journal remains separate; no autosave transaction journal churn. Corrupt retained data causes visible conflict/export choices. A quota/admission failure never turns into success or deletes existing work. No writes while canonical operation is unresolved unless recovering that exact browser operation identity; exports remain available.

## Reader refresh

POST refresh {savedOperationId,requestId} accepts a committed validated page operation, or {savedOperationId:null,requestId} for explicit retry of current repository build. One job at a time; repeat the same requestId reuses its persisted attempt, including terminal failure. Retrying a failed/interrupted attempt requires a new requestId and starts a new attempt; it does not repeat canonical Save. Job {version:1,id,state,startedAt,finishedAt,operationId,message,ownerPid,childPid}; bounded output64KiB. State running/succeeded/failed/interrupted. Persist per-attempt .author-state/page-refresh/<32hex>.json and active.json with safe atomic writes. Restart reconciles a known-dead owner and child as interrupted; ambiguous live ownership blocks retry, as specified below. Child only Node+fixed scripts/build.mjs, no shell; no arbitrary command or caller-selected workdir. Last successful static output remains usable via existing build publisher. Return job ID immediately; GET polls status. Shutdown owns/drains or terminates its child and marks interrupted. Save outcome remains committed if build fails; UI Retry refresh never reissues Save. Late responses cannot update another target or cancel a newer edit. A job is not a deployment.

## Workspace/pattern transfer

Workspace preferences use separate versioned bounded schema: panel widths180–520px, collapse booleans, selected tab/mode. Corrupt/future preferences fall back without touching page recovery. Reusable patterns store custom sections only (max12 patterns,32sections/128blocks per document caps unchanged), no managed/source projection, reference to private state, operation identity, page target, raw CSS/HTML or prepared picture bytes. Instantiation allocates fresh IDs and strips retired anchors; picture references require matching current library or visible missing-asset refusal. Transfer is inert JSON with preview/apply; corrupt/future data retained/exportable. Batch removal records retirement and cannot remove all required source projections without clear existing validation.

## Exact persistence and admission definitions (analysis1 fixes)

All object fields below are exact. SHA256 is lowercase hex of actual UTF8 bytes written by catalogJSON (stable sorted keys, two-space indentation and trailing LF); revision is computed outside the stored envelope, not self-hashed. Date fields are server UTC ISO timestamps. IDs use existing target/record validators; owner/request/revision IDs are32hex except checksum64hex.

Checkpoint envelope: {version:1,target,checkoutId,writerId,updatedAt,value}. value is the complete existing PageRecovery v1, including its full record and every unsaved prepared PNG upload regardless of whether currently attached. Binary total<=8MiB, value<=20MiB; no omission merely because current document does not reference an unsaved upload. target and checkoutId must match value and resolved server checkout. WriterId is sessionStorage per-tab identity (another browser/tab gets a new one). POST is {target,expectedRevision,writerId,value}; exact checksum CAS is required, null only for absent current data. The client first reads metadata; a foreign dirty checkpoint pauses automatic disk writes until an explicit user choice. Even same-writer updates require checksum CAS. A delayed/aborted old request can only commit its captured snapshot if CAS succeeds; client must not paint its status into a newer generation, and next update remains queued against the actual returned revision. No silent rebase after409.

GET checkpoint metadata returns {revision,current,previous}; descriptors contain {revision,writerId,updatedAt,dirty}. Full-value read separately requests an exact descriptor checksum (current or previous), otherwise409 if it changed. Current/previous each one complete envelope; replacing current first durably writes its exact bytes as previous, then durable temp/fsync/atomic rename of new current. Crash between stages retains at least old current; cleanup never removes the last valid version. A corrupt/future current or previous is retained and never overwritten automatically, including with its observed checksum; raw export is offered, canonical work/browser recovery remain independent. Explicit Clear requires matching observed checksum and separate confirmation. On create/read/restore validate value with existing recovery validator and check both exact target and checkout owner. Canonical operation unresolved: only its matching operation recovery can be checkpointed; unrelated automatic writes stop visibly.

History envelope: {version:1,id,target,createdAt,kind,value,referencedAssets}. value is PageRecovery captured by server from the validated before/after canonical candidate, not a client-supplied claimed snapshot. value.dirty=false, operation=null; checkoutId is current server. Include eligible normalized PNG bytes for both document and canonical record attached pictures within the nine/8MiB caps, including pictures no longer present in the next revision. referencedAssets is at most9 exact {id,sha256} entries for other attached/document pictures; sha256 is64hex or null if source lacks a verified byte hash. Restoration can reuse a referenced picture only if current library has matching ID and verified hash; otherwise show missing/unverified and block apply until corrected, without discarding snapshot. Native source-only pictures are never laundered into publishable uploads. Embedded PNG payloads use existing rights/decode validators. Missing/corrupt bytes prevent a falsely complete snapshot/save admission rather than silently dropping eligible pixels.

History snapshot path is server-computed target hash/id. Retention oracle: first save adds an original before snapshot plus after snapshot; subsequent saves add exactly one after snapshot. Keep newest five ordered by server captured timestamp then ID; sixth evicts exactly oldest as part of same Save file plan. No standalone deletion races or extra snapshot on operation replay. Snapshot file<=12MiB; canonical transaction stays<=64MiB. Preview admits expected history additions/pruning before reporting a candidate ready; unchanged expected history set is rechecked under commit lock. Snapshot/retention/quota failure preserves canonical content and history; successful Save must not later be labelled failed because a noncanonical UI refresh failed.

Combined active state accounting: checkpoints/current+previous, history payloads and refresh receipts only; count actual bytes, including versions scheduled to remain, subtract only exact overwritten/deleted bytes. Max256MiB and4096 files; unknown files/symlinks/devices fail closed and remain untouched. Known temporary files are validated/retained for recovery and count toward quota until safely resolved. Journal storage is the existing separate transaction system, not falsely included in this cap. Clear/prune/export are local auxiliary actions, not canonical writes. Test max-size unattached prepared pictures, current+previous accounting and corrupt retained data.

Refresh attempt schema: {version:1,id,state,startedAt,finishedAt,operationId,message,ownerPid,childPid}. id=requestId32hex, operationId32hex or null; running finishedAt=null; terminal finishedAt ISO; message<=65536 chars. Persist per-attempt receipt plus exact active pointer. Replay same requestId must match original operationId and never spawn again; new retry gets new ID. If another attempt is active,409 identifies it; it cannot be represented as refreshing the newer Save. One fixed child per checkout across author ports, using the same root lock for active admission. Lease/active state is persisted before spawn; bind owned child handle/PID immediately, never kill another process based only on a stale numeric PID. On restart retain interrupted/unknown state and refuse new work while an existing build lock/possible child remains unresolved. Known dead owner+child with no active build can become interrupted, and explicit retry can run.

Child deadline300000ms; terminate owned handle gracefully, then force after5000ms, record failed/interrupted and drain exit. Tests use injected fixed build runner/deadline without accepting them as HTTP arguments; ordinary runtime always uses fixed Node/script/cwd/no shell. Shutdown drains/terminates its owned child before close completes. Bounded logs and receipts survive server/browser navigation; client binds polling to job/generation/target. Test same-ID duplicate, failed→new-ID retry, concurrent ports, late success after another edit, timeout, shutdown and restart-active job. Unknown/pruned outcomes are not blindly rerun as if fresh. No child completion can convert a failed/unknown canonical Save into success.
