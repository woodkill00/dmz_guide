# Item crafting uses

User intent: every item page lists every recorded blueprint/recipe that consumes or uses it, with links to the resulting items. This is coverage of the admitted catalogs and captured references, not a claim of complete current-game coverage.

- FR01 Build reverse relationships by exact item IDs within a pack from catalog recipes, captured TroubleChute crafting/blueprint requirements and the separate X01 printer reference. Never join names or packs, invent costs, treat manuals as recipes or change planning/profile state.
- FR02 On every item page, show a compact Used to craft section listing distinct linked output items with per-method input quantity, available recipe link and source/context. Multiple methods stay inspectable. FOB/general recipes and X01 carried-backpack recipes stay distinct; source-only entries remain reported references, not executable recipes or blueprint ownership.
- FR02a Inventory crafting-output links use the same captured references, informational only. Private-item links stay within their saved pack using the existing local reference callback.
- FR02b User-requested visual refinement: crafting product, recipe and ingredient links use compact button-style anchors with the item name and existing item icon/fallback. Recipes use their output item's icon. Preserve keyboard navigation, names, safe private links and source attribution; never nest an image-source anchor inside a navigation anchor.
- FR02c Concise crafting layout: one Make this item section for catalog and reported methods; remove the separate producing-recipe list and repeated covered source-unlock display. Each used-to-craft output gets one icon/name button with method variants behind a disclosure. Keep all differing costs, access rules, source links and deep-link anchors; reveal a targeted method automatically. Preserve identity-only/manual references not covered by a producing method.
- FR02d Reuse a small, collapsed Used to craft preview on dashboard/Quick Collect tiles, collection rows, upgrade materials, item directory entries and Inventory's existing Crafts column. Show distinct output names/icons only, no recipe paragraphs or forecasts. Omit empty previews, keep controls outside buttons/anchors, preserve stock actions and private-pack links. Bound previews to eight chips with a clear full-item link when there are more. Do not recursively decorate chips, duplicate the Inventory column, or write profile state.
- FR03 Merge only equivalent recipes within the same context and with matching full requirements/output quantity, consumption and prerequisites. Preserve differing costs, unknowns, stations and access conditions. Broken reference endpoints must be reported, never linked to guessed destinations. Keep zero-use messaging honest.
- FR04 Preserve spoiler filtering, escaping, current-origin/referenceURL navigation and custom/private preview compatibility. Do not leak protected ingredients/output/methods. No new asset downloads or remote collection.
- SC01 Audit every catalog recipe ingredient/output edge and captured crafting/blueprint/X01 edge against the produced view; report exact counts and unresolved mapping separately. Source-only evidence must not silently disappear.
- SC02 Tests cover repeated inputs/methods, conflicting costs, unknown amounts, unrelated packs, missing endpoints, spoilers, hostile labels and referenceURL callbacks. Browser checks cover a high-use ingredient, source-only link, X01 link, mobile width and keyboard disclosure/navigation.

Clarifications: scope uses current repository evidence; direct crafting uses only, not recursive dependency chains. Blueprint ownership and inventory remain unchanged. No new user decision blocks this bounded feature.
