# Research and decisions
- Decision: retain existing recovery format/version 1. Rationale: downloadDraft already emits a named versioned envelope. Alternatives: loose JSON bypass rejected; unnecessary new version rejected. Invalid unfinished exports remain exportable but importer explains strict validation failure.
- Decision: reuse validatePayloads with complete=false, then independently require each non-upload asset to match a current source asset by full canonical asset metadata (including rights, attribution and source metadata, independent of property ordering). Rationale: recovery exports hold only new uploads and refer to repository media; never trust a path from the file. Alternatives: treating all exports as self-contained would reject legitimate unchanged media; accepting by ID alone would substitute bytes.
- Decision: preview and normalize only, retain existing explicit apply and save boundaries. Recovery revisions are historical context only; current expectedRevision stays intact.
- Decision: anchor navigation among stable existing section elements, not tab re-rendering. Existing field-level editor handles edits; no broad extraction.
- Decision: version review input is outside hidden preview, so contributors can repair version without abandoning current record. Explicit button changes draft, invalidates previews and requires validate again; no silent auto-increment.
- Decision: new Node diagnostic command rather than expanding developer-only doctor.py. Reader/author users do not need Python, Codex or specify. File inspection only, no server binding, installation or mutations.
