# Verification and update contracts

- Existing source commands remain explicit preview/check then reviewed apply. No source fetch at build/startup; no dynamic imported code execution. Fixed-host/byte/time limits and safe-path checks stay enforced.
- Verification CLI writes only under ignored test-results/content112, reads public catalog/source captures and exits nonzero on malformed/dangling/duplicate identities or broken required links. A provider-unavailable or untested fact is a named incomplete outcome, never a success for gameplay verification.
- Finding reconciliation covers every baseline identity exactly once; unknown or duplicate dispositions reject. Report totals must equal input totals. Public receipts contain summaries only.
- Reader links use existing route helpers. Quality remains the editorial owner; no second mutable review store. Data corrections never set personal progress or Checked flags.
- Touch/keyboard/browser tests use isolated synthetic contexts. Physical Android via USB/loopback forwarding requires actual connection and records; desktop emulation is labeled separately. No LAN binding, firewall change or local-service authorization expansion.
