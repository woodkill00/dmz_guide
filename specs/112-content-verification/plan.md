## Verification strategy
New behavior receives failing cases first at actual parser/quality/audit boundaries. Test unchanged source replay, malformed/foreign identity/mode rejection, source-hash review invalidation and unaffected stock/completion. No assertion/deadline reductions. Every removed baseline finding needs factual or classification evidence. Actual provider failures and physical-device absence remain visible outcomes; receipts do not create facts. Source collection alone is not an in-game test.

## Risks and alternatives
Remote markup/data can change or be partial; retain last valid snapshot and require review. Adding all source prose would clutter pages and introduce copyright issues; prefer short original summaries and typed fields. Similar names across packs are not shared inventory IDs. Physical phone access is a user-assisted dependency, not a reason to expose privileged localhost services. Baseline report may reflect legitimate uncertainty; zero warnings is not a target that permits hiding gaps.
