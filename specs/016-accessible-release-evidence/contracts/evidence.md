# Data model
Image-bearing records optionally add imageDescriptions: array of at most9 {assetId,text,decorative}. IDs unique and attached via assetId/assetIds. Text<=1000; decorative true iff text empty; meaningful text must trim nonempty. Legacy absent allowed; unknown fields rejected. Current schema version remains compatible additive metadata for new readers; old strict readers may reject enriched packs, documented rather than claiming old-reader support.
Recovery inventory: complete, transactionCount, fileCount, bytes, transactions[{transactionId,fileCount,bytes,archiveEligible,reasons}], warnings. Incomplete totals explicitly partial. Read-only bounded snapshot, races prevent positive eligibility.
Release manifest v2: format/version, files mapping member to {sha256,bytes}, archiveMembers sorted list, manifestSelfDigestExcluded, identity. Identity source revision and dirty/unknown state plus actual source/schema/build hashes. No signature/authorship assertion.

## Captured build identity (integrator-approved hook; reviewer gate pending)
During existing withRepositorySnapshot callback, use catalog.files captured bytes and materialized bundled.files bytes, plus stable assembled catalogJSON(entry.pack), to record content/media hashes. These exact captured bytes remain valid if a subsequent authorized save changes live content; never reread live content to reject that captured snapshot. No second/nested snapshot or lock acquisition.
Before generate reads executable/schema/site inputs, capture sorted regular-file hashes under src/, schemas/, scripts/, plus content/site.json, package.json and package-lock.json; bound to50000 files/128MiB total/64MiB individual/depth16, reject symlink/nonregular. Rehash these same non-catalog inputs immediately before identity emit; differences/added/removed input fail generation and retain OLD through existing publishBuild. No staging/promotion/mutex change.
Identity uses format/version, Node runtime major, deterministic algorithm version, descriptive Git HEAD and dirty/unknown (Git failures => unknown, no failure or invented clean state), sourceFiles, capturedCatalogFiles, capturedPackHashes, capturedMediaFiles, schemaHash. No timestamp or path outside repository. Hash sorted canonical identity components to get buildId. Emit assets/build-identity.json through existing emit() so staged validation covers it.
Packaging requires identity file, verifies its format and self-derived buildId plus non-catalog sourceFiles against current checkout (stale source/code build rejected); it must not re-read mutable catalog/media to relabel a valid captured snapshot stale. Source revision is descriptive build-time observation, not a claim the build is identical to Git checkout or trusted authorship. Manifest embeds identity digest/buildId and schema evidence from emitted identity; all identity bytes covered by payload digest. A tampered manifest+payload cannot be authenticated without a separately trusted digest.
Identity also includes outputFiles: exact sorted generated staged file digests from existing inventory before identity emit. The identity itself is the only explicit self-hash exclusion. Packaging verifies complete dist file-set and all output hashes against outputFiles before adding identity to release payload; tampered/missing/extra dist content rejects packaging. Static imports run before generate, so source hashes describe observed stable source inputs across generation, NOT authenticated executing-code provenance or a pre-execution snapshot. This limitation is explicit in identity's evidenceScope string.

## Windows package stat compatibility amendment (2026-10-22)
For bounded package reads, Windows cross-interface path-to-fd comparison uses dev/ino/size/mtime_ns, not ctime_ns: supported CPython Windows versions expose different ctime semantics through path versus descriptor APIs. Retain full five-field (including ctime_ns) path-before/path-after-open/path-after-read comparisons and full five-field fd-open/fd-after-read comparison. Non-Windows additionally retains full five-field cross-interface comparison. Every path observation repeats existing safe_stat ancestor/no-symlink checks; regular-file, bounded byte/count, exact size and payload/source hashes remain mandatory. No timestamp rounding, fallback retries or ctime-only mutation acceptance within either interface. This is bounded race detection, not a claim of hostile concurrent filesystem atomicity.
Before accepting platform success, run native stable and deliberately mutating tempfile probes on actual Windows and record sys.version/sys.executable/platform plus bounded stat signatures. Do not infer the failing runtime's interpreter from a different CI job. See reproduction/windows-stat-interfaces.md for primary sources and chronology.
