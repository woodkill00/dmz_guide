# DMZ Guide: recommended product and build plan

> Historical planning snapshot (21 October 2026), preserved as product context. References below to proposed setup, pending licensing or absent repository authorization describe the earlier planning stage, not current repository status. The repository is now being bootstrapped; original project code is MIT licensed. See [current README](README.md) and [current Spec Kit lifecycle](docs/spec-kit-cycle.md) for active setup and process. Product features and production data remain unimplemented. This snapshot does not authorize external actions.

## What to build
A mobile-first, default-dark field guide that connects four actions: find what an item does, choose an upgrade, understand what to collect now versus later, and find relevant locations. Keep public guides readable without accounts. Let players own their inventory/progress data and let contributors edit and transfer validated item, recipe and picture packs.

The strongest direction is not “more pages” or an unproven claim to be the first planner. It is a coherent journey with explainable numbers, source confidence, recovery from mistakes and portable data. Existing DMZ sites already offer crafting planners; this project should earn trust through execution rather than uniqueness claims.

## What the research established
Current official sources confirm Modern Warfare 4 and DMZ. The uploaded images provide useful interface and upgrade examples, but their exact build/capture date and redistribution permission are not established. Two official sources appear to disagree about a printer unlock level, so that fact stays disputed rather than being guessed. Competing guide sites and direct DMZ tools informed navigation, source labels and planning patterns; blocked sites were not treated as inspected.

## The biggest decisions
- Static-first public guide with small interactive planner/map/editor modules, rather than a server-heavy app from day one.
- Separate public content from local private inventory/progress; backup and recovery before accounts.
- Explainable requirements plan plus a separate executable-now schedule. Shared stock, batch yields, one-time unlocks and priority reservations cannot be collapsed into simple subtraction.
- Private editing is not public publishing. Full picture-pack portability includes actual bounded assets, not just links.
- Original/licensed map imagery with a fully useful location list; no copied map database or unsupported “fastest route” claims.
- Discord link and reviewed corrections first. Bots, live squads and cloud sync are optional later projects, not requirements for reading the guide.

## Delivery order
1. Evidence, data contracts and visual prototype.
2. Searchable guide and item/recipe details.
3. One useful inventory-aware plan, then shared multi-goal now/later planning.
4. Safe data editor and portable picture packs.
5. Maps/location intelligence, progression/story, community and release checks.

The first useful core is smaller than the full requested product. Maps, story, progression, editor and community remain tracked delivery commitments; they are not silently dropped. Optional offline downloads, sync, bots and optimization need their own evidence and scope decisions.

## Quality bar
The plan includes 25 explicit acceptance cases plus import attacks, responsive visual review, accessibility, storage recovery and performance measurement. Tests have not been run because no implementation has been created. Independent review found and corrected real modeling and sequencing issues; remaining gates are primarily content verification, rights, owner decisions and later execution evidence.

## Small owner-decision shortlist
Before implementation kickoff, choose the intended first release scope and target game/build. Before publishing, confirm asset/data rights and repository license, hosting/domain/budget, and the Discord server plus moderation owners. These do not block the evidence-independent planning work already completed.

## What is delivered
Repository-ready planning documents, researched alternatives, decision records, source/coverage register, implementation task sequence and a current Spec Kit execution guide. This is not an initialized Spec Kit project or a runtime build. No repository commit, deployment, account setup or credentials change was made.
